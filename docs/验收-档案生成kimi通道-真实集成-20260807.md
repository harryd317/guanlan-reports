# 验收：档案生成 Kimi 通道真实集成（2026-08-07）

## 1. 结论

本批在生产等效只读环境中，用 Kimi 通道为“动物保健Ⅱ”生成一篇真实初稿。调用先完成一次 Moonshot 内建 `$web_search`，再生成七节正文。初稿通过规格 v2 校验：七节齐全，核心股票 5 只，证据节含 6 个链接和事实日期。

本批没有合并或部署。初稿只作为验收证据保存，保留“AI草稿，未审不入库”标识；它没有写入档案队列，也没有进入 S8 已发布门槛。

## 2. 配置与密钥边界

- 配置文件：`~/.config/guanlan/kimi.env`，位于仓库外，权限 `0600`。
- 服务只通过 `kimi_config()` 读取 `KIMI_API_KEY`。测试、日志、报告、初稿和镜像均不保存密钥。
- 验收未读取或打印密钥值。脱敏产物扫描结果为 0 个阻断项、0 个合成白名单项。
- 错误路径只返回固定提示，不回显响应正文、认证头或异常中的密钥片段。

## 3. 通道选择与协议修正

默认生成通道仍为 `kimi`；`claude_code` 与 `api` 只在操作者显式改配置后启用，运行时不静默降级。

Moonshot 官方文档说明：K2.6 关闭思考后可使用内建 `$web_search`，但 K2.6 不支持 `tool_choice="required"`。因此本批没有发送不受支持的强制参数。流水线改为两段：

1. 首轮只接收行业名，要求模型调用 `$web_search`。若模型直接回答，服务立即拒绝。
2. 服务原样回传内建搜索参数，再注入同一数据骨架和 `industry-archive-v2.1-web` 模板生成初稿。

首轮真实调用返回 `finish_reason=tool_calls`，工具名为 `$web_search`；第二轮返回正文。模型使用 `kimi-k2.6`，请求体设置 `thinking.type=disabled`。K3 仍可由配置选择，但本批的硬要求是内建 `$web_search`，所以验收采用官方联网搜索指南推荐的 K2.6 路径。

参考：

- https://platform.kimi.com/docs/guide/use-web-search
- https://platform.kimi.com/docs/guide/kimi-k2-6-quickstart
- https://platform.kimi.com/docs/guide/migrating-from-openai-to-kimi

## 6. 旧源 API 渲染探针

上轮错误由等效克隆的旧路径引起：`INDUSTRY_THERMOMETER_DB_PATH` 被指向不含快照表的旧 S3 库，接口报 `no such table: industry_thermometer_snapshots`。本批改用生产温度计 sidecar 的只读 SQLite 快照。

路径修正后，真实数据又暴露日期不齐：温度计快照早于行情库。名单接口现在返回诚实的只读空态“温度计与行情日期未对齐，名单暂不展示”，不再返回 500，也不伪称“今日无”。

应用内浏览器对今天页和连阳页逐路由整页重载，覆盖 393×852、430×900、1280×900，共 6 行。结果为 6/6：加载占位 0、可见错误 0、控制台错误 0、旧源错误 0；页面根节点横纵尺寸均相等。
