# Codex、Claude 会话经 Hermes 同步到 Obsidian 设计

> 日期：2026-07-19
> 状态：用户已批准方案 B
> 回填起点：2026-06-20 00:00:00 Asia/Shanghai
> Obsidian Vault：`~/obsidian-knowledge-base`

## 1. 目标

系统自动收集本机全部 Codex 和 Claude 主会话中用户可见的文字，将其转换为可读、可追溯、已脱敏的 Markdown 原文，再由本机 Hermes 生成每日双脑摘要。Obsidian 是共同事实层；Codex、Claude 和人都从同一份原文与摘要追溯历史。

系统必须做到：

1. 覆盖所有项目的 Codex 和 Claude 主会话。
2. 首次回填最近 30 天，此后持续增量同步。
3. 保留用户与 AI 之间的可见文字，排除平台内部数据。
4. 原文归档不依赖 Hermes；Hermes 故障只延迟摘要。
5. 中断、重试、活动会话继续追加时不重复消息。
6. 新链路复用现有 Vault Git 发布任务，不另建第二套提交和推送流程。

## 2. 方案选择

### 方案 A：复制原始 JSONL

该方案保留的平台数据最多，但会把系统指令、工具输出、加密推理、Base64 图片、凭证和用量元数据带入 Vault。文件体量大，隐私风险高，Obsidian 阅读体验差。不采用。

### 方案 B：可见原文归档 + Hermes 分层摘要

确定性解析器只提取用户和助手的可见文字，先写人类可读原文，再让 Hermes 基于已脱敏原文生成摘要。它同时满足完整性、可追溯性和安全性。采用。

### 方案 C：只保存 Hermes 摘要

该方案体量最小，但摘要会遗漏细节，Hermes 不可用时整条链路停摆，也无法核对摘要中的误解。不采用。

## 3. 数据边界

### 3.1 数据源

- Codex：`~/.codex/sessions/**/*.jsonl`
- Claude：`~/.claude/projects/**/*.jsonl`

第一次执行处理 `2026-06-20 00:00:00` 至执行时刻的会话。日期归属、回填起点和定时任务一律使用 `ZoneInfo("Asia/Shanghai")`。

只收录主会话。Claude `subagents/` 下的内部代理会话不单独归档；其用户可见结果已出现在主会话中。Codex 的内部协作事件也不单独归档。这条边界防止同一结论多次入库。

### 3.2 收录内容

每个会话归档包含：

- 平台：Codex 或 Claude；
- 会话 ID；
- 开始时间和每条消息时间；
- 项目或工作目录；
- 用户可见的用户文字；
- 用户可见的助手文字。

附件只记录可见文件名或类型，不复制二进制内容。

### 3.3 排除内容

解析器必须排除：

- system、developer 和平台动态指令；
- 隐藏推理、加密内容和压缩上下文；
- 工具调用、工具输出、终端日志和浏览器输出；
- 代理内部队列、诊断、用量和速率限制元数据；
- Base64、图片字节、音频字节和其他大块二进制表示；
- 空消息与只含工具结果的消息。

## 4. 输出结构

### 4.1 可读原文

原文按日期和平台保存：

```text
90-系统/AI会话/原文/YYYY-MM-DD/
├── Codex-<session-id>.md
└── Claude-<session-id>.md
```

一个会话跨越多个自然日时，每条消息按 Asia/Shanghai 日期进入对应日的文件；文件名保留同一会话 ID，便于跨日追溯。

原文文件使用稳定头部和消息块：

```markdown
---
platform: codex
session_id: ...
date: 2026-07-19
project: /absolute/project/path
generated_by: ai-session-sync
---

## 10:15 用户

消息正文

## 10:17 Codex

回复正文
```

脚本管理这些文件。人和 AI 不在其中手工编辑。

### 4.2 每日双脑摘要

Hermes 将当日已脱敏原文汇总到：

```text
20-AI复核/YYYY-MM-DD-AI双脑日报.md
```

日报包含以下固定栏目：

1. 今日完成；
2. 用户拍板与约束；
3. 关键结论和证据；
4. 未完成待办；
5. 分歧、失败尝试和风险；
6. Codex 给 Claude 的接力信息；
7. Claude 给 Codex 的接力信息；
8. 来源会话链接。

每条可核对的事实必须链接到对应原文。Hermes 可以压缩、合并和标注冲突，不得补写原文之外的事实。

## 5. 解析与去重

### 5.1 平台适配器

Codex 适配器只接受明确标记为用户或助手可见消息的事件。它不从 `event_msg` 和 `response_item` 同时复制同一条用户消息；适配器使用稳定消息 ID 或内容指纹去重。

Claude 适配器只读取顶层 `user` 和 `assistant` 记录的文字内容块。`tool_use`、`tool_result`、`thinking`、`attachment`、`queue-operation` 和 `last-prompt` 不进入原文。

### 5.2 增量状态

运行状态放在 `~/.local/state/ai-session-sync/`，不进入 Vault。状态至少记录：

- 源文件的平台、绝对路径、大小和最后修改时间；
- 已接受消息的稳定 ID 或 SHA-256 指纹；
- 每日原文指纹；
- 每日 Hermes 摘要指纹和最后成功时间。

状态文件通过同目录临时文件、`fsync` 和 `os.replace` 原子替换。仅当对应 Vault 文件成功原子替换后，程序才推进原文状态。

源 JSONL 被截断、替换或最后一行未写完时，程序重新扫描该文件，依靠消息指纹去重。单个损坏行会记录文件和行号，不阻断其他会话。

## 6. 脱敏与安全

脱敏先于任何 Vault 写入和 Hermes 调用。程序将可识别的凭证原位替换为以下标记：

```text
[已脱敏：OpenAI API key]
[已脱敏：Bearer token]
[已脱敏：Webhook]
```

最少覆盖：

- OpenAI 风格的 `sk-...` 凭证；
- `Authorization: Bearer ...`；
- `API_SERVER_KEY=...` 等凭证赋值；
- Server酱 SendKey；
- 企业微信、Slack、Discord 和常见通知 Webhook；
- PEM/OpenSSH 私钥块；
- 超过限制的 Base64 或高熵长串。

原始 JSONL 永不复制进 Vault。日志只记录计数、文件、行号和凭证类型，不记录命中文本。

## 7. Hermes 摘要

程序通过现有本机网关 `127.0.0.1:8642` 调用 Hermes，从 `~/.hermes/.env` 读取认证信息，不输出凭证。

当日原文超过单次输入上限时，程序按会话边界分块，先生成带来源的块摘要，再合并为当日日报。分块不拆分单条消息；超长单条消息保留原文，摘要材料中明确标注截断。

摘要更新使用当日原文指纹幂等判定。指纹未变时不调用 Hermes。Hermes 超时、返回空内容、输出包含敏感信息或缺少固定栏目时，程序不更新日报，也不推进摘要指纹。

## 8. 调度与发布

新的 launchd 任务使用两种模式：

- `collect`：每 15 分钟扫描新消息并原子更新可读原文；
- `digest`：每天 05:50、11:50、17:50 和 23:50 尝试更新当日双脑日报。

摘要任务提前于现有 05:59、11:59、17:59 和 23:59 的 Vault 复核任务，让新日报进入当班复核。

新程序不执行 `git add`、`git commit`、`git pull` 或 `git push`。现有 `com.harryd317.vault-autosync` 每 15 分钟发布 Vault 所有原子写入。这使 Codex、Claude、Hermes、Obsidian 手工编辑和会话同步共用一条 Git 链路。

日志写入 `~/Library/Logs/ai-session-sync.log`，包含运行时间、模式、扫描会话数、新消息数、脱敏计数、损坏行计数和失败阶段。

## 9. 失败与恢复

- 单个 JSONL 损坏：记录文件和行号，继续其他会话。
- Vault 不存在或不可写：本轮失败，不推进任何状态。
- 原子替换失败：保留旧文件，不推进对应状态。
- Hermes 不可用：原文已保存；日报保留上一版；下个摘要时段重试。
- 摘要验证失败：将原始响应放在状态目录的临时失败文件中，不写入 Vault；文件次日自动删除。
- Mac 睡眠或 launchd 错过时段：下次 `collect` 扫描全部活动源文件；下次 `digest` 补齐指纹落后的日期。

任务用文件锁防止 `collect`、`digest` 和回填并发写入同一份归档。锁文件放在 `~/.local/state/ai-session-sync/run.lock`，进程退出时由操作系统释放。

## 10. 回填

回填命令显式传入起点 `2026-06-20`。它先完成所有原文归档，再按日期从旧到新生成 Hermes 日报。每个日期单独推进摘要指纹；中途失败时，下次从第一个落后日期继续。

回填不保证复原已被平台清理或未落盘的会话。验收只以回填时仍存在于两个会话目录的主会话为准。

## 11. 测试策略

实施使用 Python 标准库和 TDD。测试使用临时目录构造小型 Codex、Claude 会话，不读写真实会话和生产 Vault。

至少覆盖：

1. Codex 用户/助手文字提取与重复事件去重；
2. Claude 文字块提取和工具块排除；
3. 跨日会话拆分与 Asia/Shanghai 日期口径；
4. 主会话收录与子代理排除；
5. 密钥、Bearer、Webhook、私钥块和 Base64 脱敏；
6. 未完成 JSONL 尾行和单行损坏恢复；
7. 重跑零差异、活动会话增量追加和源文件截断；
8. Vault 写入失败不推进状态；
9. Hermes 故障不阻断原文，且摘要指纹保持不变；
10. 超长当日材料的分块、合并和来源链接；
11. 回填中断后从落后日期继续；
12. launchd plist 语法、路径、调度和日志契约。

安装前在临时 Vault 完成端到端验证。生产验收按以下顺序进行：`dry-run` 统计、最近 30 天原文回填、抽样查看脱敏文件、Hermes 日报回填、第二次幂等重跑、launchd 加载和实际增量消息验证。

## 12. 验收标准

当且仅当以下条件全部成立，任务完成：

- `dry-run` 列出最近 30 天的 Codex 和 Claude 主会话数，且不写入文件或状态；
- 存量主会话按日期归档，原始 JSONL 不进入 Vault；
- 抽样比对 Codex 和 Claude 各至少 3 个会话，可见文字顺序正确，工具和内部内容未混入；
- 使用敏感信息扫描器检查全部新增原文与日报，结果为零未脱敏命中；
- 回填日期中的每个有效会话日都有原文，并有对应 Hermes 日报或明确失败记录；
- 第二次运行不产生重复消息、重复文件或无意义 Git diff；
- Hermes 离线演练中原文照常写入，摘要状态不前进；
- launchd 的收集和摘要任务已加载，最近一次退出码为 0；
- 现有 screener 服务、交易规则、生产数据库和定时扫描未改动；
- Vault 自动发布后，本地 `main` 与 `origin/main` 一致。

## 13. 非目标

本期不做：

- 不保存隐藏推理、系统提示或工具输出；
- 不同步图片、音频、视频或附件正文；
- 不修改 Codex 或 Claude 原始会话文件；
- 不将 Obsidian 摘要自动注入平台隐藏上下文；
- 不替换现有 screener 文档同步、Vault Git 发布或每日复核任务；
- 不删除 30 天之前的原始会话，也不自动回填它们。
