## 三、排查与根因

### 观察

同一等效实例的普通视口截图显示五页布局正常。浏览器探针同时确认：

- 桌面 `innerWidth/clientWidth/scrollWidth` 均为 `1440`；
- 手机 `innerWidth/clientWidth/scrollWidth` 均为 `390`；
- 今天、股票池、我的和设置的关键内容矩形宽高大于零；
- 手机“我的”主容器宽 `358px`，不存在单字列；
- 静态资源和业务 API 正常返回，页面没有稳定的加载错误。

历史会话记录显示，首次生产验收先把浏览器视口设为 `1440×900` 或 `390×844`，随后统一调用：

```javascript
await tab.screenshot({ fullPage: true })
```

本轮在等效实例做单变量 A/B：

1. 保持页面、进程、视口、数据和路由不变；
2. 普通 `tab.screenshot()` 生成正常画面；
3. 改为 `tab.screenshot({fullPage:true})`；
4. 桌面今天页立即变为空白图，手机“我的”立即变为窄列、逐字纵排。

诊断对照位于：

```text
docs/screenshots/t7-production-equivalent/20260731/diagnostic/
```

### 根因

根因是内置浏览器在“显式视口覆盖 + `fullPage`”组合下的整页截图缺陷。它生成的栅格图与当时的正确 DOM 布局不一致：

- 今天页整页截图丢失主体，形成空白图；
- 长手机页面的整页截图错误重排宽度，形成窄列和纵排；
- 页面本身、模板、静态路径和响应式 CSS 没有出现相同异常。

首次验收把损坏的取证图片当成生产页面的真实画面，因而触发了正确且保守的回滚。回滚动作符合“任一生产视觉异常立即回滚”的授权。

另一个证据问题是截图返回 JPEG 字节，但旧流程使用 `.png` 扩展名。该命名错误不改变画面，却会降低后续工具对证据格式的判断可靠性。

### 已排除项

| 候选原因 | 证据 | 结论 |
| --- | --- | --- |
| 模板或 CSS 缺陷 | 普通视口截图与关键矩形正常；仅切换 `fullPage` 即复现 | 排除 |
| 静态资源路径或工作目录 | 等效实例使用同一启动链与 `FileResponse`，资源和页面均成功加载 | 排除 |
| 数据库内容或写入 | 三套副本只读；前后哈希一致；页面 API 返回有效数据 | 排除 |
| 缓存混版 | 加查询参数重载后结果不变；普通/整页截图可在同一页面连续切换 | 排除 |
| 截图字节写入损坏 | 返回对象是有效 `Uint8Array`，文件可解码；异常由截图模式决定 | 排除 |
