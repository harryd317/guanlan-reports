# 全局 AI 会话分类与可验证接力闭环设计

> 日期：2026-07-21
>
> 状态：用户已批准
>
> 适用范围：本机全部 Codex 与 Claude 主会话
>
> 依赖：Hermes 本机网关、Obsidian Vault、现有 Vault Git 发布任务
>
> 前置设计：`docs/superpowers/specs/2026-07-19-ai-session-sync-design.md`

## 1. 目标

本设计把现有“会话归档流水线”升级为“可验证的知识接力闭环”。系统收集全部项目的 Codex 与 Claude 主会话，先脱敏，再自动分类，随后生成按项目隔离的接力资料。新会话只读取当前项目资料；它产生的新反馈再次进入同一链路。

系统必须完成以下循环：

```text
主会话 → 脱敏 → 分类 → 归档 → Hermes 摘要 → Obsidian/Git
   ↑                                                    ↓
新反馈归档 ← 新会话继续工作 ← 读取回执 ← 按项目自动接班
```

“文件已经生成”不代表闭环完成。系统仅在采集、脱敏、分类、归档、摘要、发布、读取和反馈八个阶段都有可核验回执时，才把该轮标记为“已闭环”。

## 2. 对前置设计的调整

本设计保留前置设计的可见文字归档、原子写入、消息指纹、Hermes 零工具权限和 Vault 统一发布原则，并调整以下范围：

1. 日报从“全局混合日报”改为“项目日报 + 项目当前接力 + 全局总览”。
2. 新增规则优先、Hermes 补充的自动分类器。
3. 新增身份别名、精确资金去除和独立安全复检。
4. 新增 Codex、Claude 的显式自动接班与读取回执。
5. 将固定四次摘要升级为变更驱动摘要，并保留固定时点作为兜底。
6. 新增发布回执、反馈回执、闭环状态和故障告警。
7. 删除前置设计中“不自动注入摘要”可能造成的歧义：系统仍不注入隐藏上下文，但会通过公开项目指令显式调用接班程序。

## 3. 当前必须修复的缺口

实施前必须承认并处理以下已验证问题：

- Codex 子代理会话会被当作主会话归档，并已进入 Hermes 日报来源。
- 当前脱敏器漏识别 Server酱 SendKey 等凭证格式。
- 当前日报混合不同项目，无法安全地自动回读。
- Codex 与 Claude 新会话没有读取日报的硬性步骤，也没有读取回执。
- AI 会话同步实现仍在本地功能分支，未进入 `main` 和远端。
- 旧 screener 文档同步器会在分阶段失败后返回成功，退出码不能证明任务成功。

新系统上线前必须隔离受污染产物、重新生成受管资料、合并并推送源码。

## 4. 设计原则

### 4.1 先确定性，后 AI

目录、Git 根目录、远端地址、平台元数据和项目注册表先决定项目。只有确定性信息不足时，Hermes 才参与语义分类。Hermes 不能覆盖确定性项目归属。

### 4.2 先脱敏，后分类

系统在任何 Hermes 调用和 Vault 写入前完成脱敏。分类器、摘要器和 Git 只能看到脱敏文本。

### 4.3 项目隔离

每个项目拥有独立日报和当前接力。新会话读取当前项目资料，不读取其他项目的原文和详细日报。全局总览只包含项目名、状态和跨项目待办。

### 4.4 事实可追溯

Hermes 产出的项目事实、拍板、风险和待办必须链接到受管原文。无来源的事实不能进入当前接力。

### 4.5 失败显式化

任何阶段失败都返回非零退出码，并保留上一份有效产物。任务不能用“最终执行完成”掩盖中间失败。

### 4.6 原始数据不扩散

Codex 与 Claude 原始会话文件保持原位。系统不复制未脱敏原文，不修改平台源文件，也不把隔离内容发送给 Hermes。

## 5. 系统组件

系统由八个边界明确的组件组成。

### 5.1 源适配器

源适配器解析 Codex 和 Claude JSONL，只产出用户可见的主会话文字。它读取会话元数据后先判断主会话身份，再解析消息。

Codex 适配器必须跳过 `session_meta.payload.source.subagent` 存在的会话，以及平台动态指令、工具输出、协作事件和隐藏内容。Claude 适配器必须跳过 `subagents/`、`isMeta`、工具块、思考块、附件正文和平台动态提醒。

适配器输出稳定会话 ID、消息 ID、时间、角色、文本、工作目录、Git 根和平台。无法确认可见性的记录不进入后续阶段。

### 5.2 分级脱敏器

分级脱敏器处理凭证、身份和资金隐私，并保留投资与工程判断所需的数据。第 8 节定义完整策略。

### 5.3 独立安全复检器

安全复检器使用独立于脱敏器的规则。它不复用同一正则集合。复检发现疑似凭证时，系统把消息放入本机隔离区，停止该消息的分类、归档和摘要。

### 5.4 分类路由器

分类路由器按消息段落而非整场会话分配主分类、项目、主题、内容类型和敏感等级。它维护项目注册表与别名，自动创建稳定的新项目，并阻止同义项目分裂。

### 5.5 归档写入器

归档写入器将脱敏后的主会话写入受管 Markdown。它保留一份原文，分类索引通过来源链接引用原文，不复制正文。

### 5.6 Hermes 分类与摘要器

Hermes 只读取已通过安全复检的受管文本。API Server 工具集必须为空，请求体继续声明 `tools: []` 和 `tool_choice: none`。分类输出和摘要输出都要经过结构、来源和敏感信息校验。

### 5.7 接班客户端

接班客户端根据当前目录、Git 根和项目注册表识别项目，读取项目当前接力、最新日报和少量全局约束。它写入读取回执，不使用隐藏提示注入。

### 5.8 闭环状态器

状态器汇总阶段回执，输出项目级健康状态。它负责重试、告警和“已闭环”判定，不生成业务摘要。

## 6. 分类模型

### 6.1 固定顶层分类

顶层分类保持稳定：

1. 项目研发；
2. 投资财务；
3. 个人事务；
4. 知识学习；
5. 系统运维；
6. 综合临时。

项目是顶层分类下的动态实体，例如 `screener`、`Hermes` 或新建项目。主题标签可以扩展，但不能替代项目。

### 6.2 每个消息段的分类字段

每个可归档消息段至少包含：

```yaml
primary_category: 项目研发
project_id: screener
topic_tags: [风险控制, 回测]
content_type: decision
sensitivity: financial_private
confidence: 1.0
classification_source: git_root
```

`content_type` 的允许值是 `decision`、`constraint`、`conclusion`、`todo`、`failure`、`knowledge` 和 `conversation`。

### 6.3 分类优先级

分类器按以下顺序执行：

1. 精确匹配项目注册表中的 Git 根、远端地址或工作目录；
2. 匹配已登记的项目别名；
3. 读取平台项目元数据；
4. 将脱敏文本交给 Hermes 语义分类；
5. 将低置信度内容放入临时队列，夜间二次归纳；
6. 二次归纳仍无法确定时，归入“综合临时”。

确定性分类的置信度为 `1.0`。Hermes 分类置信度达到 `0.85` 才能直接归入已有项目；低于 `0.85` 的内容进入临时队列。

### 6.4 多主题会话

系统以连续的用户消息和助手回复为一个分类段。一场会话可以属于多个项目。原文只保存一次，各项目日报通过消息锚点链接到同一原文。

系统提示、推荐插件、环境上下文和权限说明即使以 `user` 角色落盘，也不能成为分类段。适配器必须按平台元数据和受管包络标记排除这些内容。

### 6.5 自动创建项目

系统在以下情形自动创建项目：

- 首次发现新的 Git 根或远端地址时立即创建；
- 非代码主题在七天内出现至少三个相关分类段，并且来自至少两个会话或两个自然日时创建；
- 用户明确命名一个持续项目时立即创建。

不足条件的内容留在“综合临时”，不会产生一次性项目。

### 6.6 别名与防碎片

相同 Git 根或远端地址的名称自动合并。纯语义别名只有在夜间二次分类置信度达到 `0.95` 时才自动合并。项目注册表保留规范 ID、显示名、别名、分类、根目录和创建证据。合并只更新路由和索引，不改写历史原文。

## 7. 项目注册表

项目注册表保存为受管 YAML：

```text
90-系统/AI会话/项目注册表.yaml
```

路径使用 `$HOME` 相对表示，避免写入本机用户名。每个项目包含：

```yaml
id: screener
name: A股纪律投研台
category: 项目研发
roots:
  - $HOME/云慧养/zmu_gitee/screener
git_remotes:
  - github-personal:harryd317/screener.git
aliases:
  - 炒股工具
  - 股票系统
  - screener
created_by: git_root
```

状态目录保存注册表指纹。注册表损坏时，系统保留上一份有效版本并停止自动建项。

## 8. 分级脱敏

### 8.1 S0：凭证

凭证必须完全替换，不能保留部分字符。至少覆盖：

- OpenAI、Anthropic、OpenRouter 和其他 `sk-` 风格密钥；
- `Authorization: Bearer`；
- `API_KEY`、`TOKEN`、`SECRET`、`PASSWORD`、`SENDKEY`、`CREDENTIAL` 等赋值；
- Server酱 `SCT...` 和 `sctp...` SendKey；
- 企业微信、Slack、Discord 和其他 Webhook；
- Cookie、会话令牌、PEM/OpenSSH 私钥；
- 高熵长串和超长 Base64。

替换格式只暴露类别，例如 `[已脱敏：Server酱密钥]`。

### 8.2 S1：身份与账户

券商账号、银行卡号、身份证号、手机号、邮箱和可识别账户名替换为稳定别名，例如 `保证金账户-7F3A`。

别名通过本机 HMAC 密钥生成稳定标识。密钥保存于：

```text
~/.local/state/ai-session-sync/pseudonym.key
```

文件权限固定为 `0600`，不进入 Vault、日志或 Git。系统不得使用可枚举的裸 SHA 哈希替代 HMAC。

### 8.3 S2：精确资金

AI 不需要知道精确资产。以下金额必须去精确化：

- 总资产、现金、余额和购买力；
- 持仓市值和成交金额；
- 盈亏金额和累计亏损金额；
- 股票、期权和基金的精确持有数量。

金额使用以下固定区间：

```text
不足1万元 / 1万–5万元 / 5万–10万元 / 10万–30万元
30万–50万元 / 50万–100万元 / 100万–300万元
300万–500万元 / 500万–1000万元 / 1000万元以上
```

同币种且分母可靠时，持仓市值转换为仓位比例，盈亏金额转换为收益率。分母缺失或币种不一致时保留金额区间和币种，不猜测比例。无法安全换算的数量写为 `[数量已隐藏]`。

### 8.4 S3：决策数据

以下数据原样保留：

- 股票、基金和期权代码；
- 现价、成本价、买点、止损线、均线和目标价；
- 仓位比例、收益率、回撤率和风险预算比例；
- 买卖理由、规则、拍板、失败尝试和复盘结论。

该层保证隐私处理不破坏投资和工程判断。

### 8.5 复检与隔离

复检器在脱敏后扫描全文。任何 S0 或 S1 命中都会阻断该消息。被阻断内容写入权限为 `0700` 的本机隔离目录：

```text
~/.local/state/ai-session-sync/quarantine/
```

隔离记录只保存会话 ID、消息 ID、命中类别和本机源路径。日志不记录命中文本。

## 9. Obsidian 结构

Vault 使用以下结构：

```text
90-系统/AI会话/
├── 原文/YYYY-MM-DD/<Platform>-<session-id>.md
├── 分类索引/YYYY-MM-DD.md
└── 项目注册表.yaml

20-AI复核/
├── 全局/当前总览.md
└── 项目/<project-id>/
    ├── 当前接力.md
    └── 日报/YYYY-MM-DD.md
```

原文头部增加脱敏策略版本、分类版本和项目列表：

```yaml
redaction_policy: 2
classification_policy: 1
projects: [screener]
generated_by: ai-session-sync
```

人和 AI 不手工编辑受管原文、分类索引和日报。项目当前接力由程序原子更新，并保留来源链接。

## 10. 项目日报与当前接力

### 10.1 项目日报

每个项目按日生成独立日报，固定包含：

1. 今日完成；
2. 用户拍板与约束；
3. 关键结论和证据；
4. 未完成待办；
5. 分歧、失败尝试和风险；
6. Codex 给 Claude 的接力信息；
7. Claude 给 Codex 的接力信息；
8. 来源会话链接。

每条非“暂无”事实必须链接到该项目当日允许的消息锚点。跨项目事实只能链接，不能复制正文。

### 10.2 项目当前接力

当前接力是滚动状态，不是日报拼接。它包含：

- 项目目标和当前阶段；
- 已生效的用户拍板与硬约束；
- 最新完成项和证据；
- 未完成待办及优先级；
- 已知风险、失败尝试和禁止重复路径；
- 最近一次有效日报和原文来源。

Hermes 更新当前接力时必须保留仍有效的旧约束，明确标记已完成待办，并为新增事实附来源。无法证明失效的约束不能删除。

### 10.3 全局总览

全局总览只包含项目名、状态、最近活动、跨项目待办和全局工作偏好。它不包含项目原文、精确资金、项目内部细节或凭证类别命中情况。

## 11. 自动接班

### 11.1 显式调用

安装程序在 Codex 全局 `AGENTS.md` 和 Claude 全局 `CLAUDE.md` 中加入受管指令块。Codex 指令要求每次主会话开始项目工作前运行：

```text
ai-session-handoff read --platform codex --session-id "$CODEX_THREAD_ID" --cwd "$PWD"
```

Claude 安装器同时注册 `SessionStart` 身份绑定钩子。钩子只把平台提供的 `session_id` 和 `cwd` 传给 `ai-session-handoff bind`，不注入接力正文；`CLAUDE.md` 再显式要求 Claude 调用 `ai-session-handoff read --platform claude --cwd "$PWD"` 并读取返回文件。

接班程序只接受平台提供的权威会话 ID。ID 缺失或身份绑定产生多个候选时，程序可以展示接力，但不能写 `consumed` 回执。

这一步是公开、可审计的项目指令，不是隐藏上下文注入。受管指令块带开始和结束标记；重复安装只更新该块，不覆盖用户其他指令。Claude 身份绑定钩子也使用独立受管标记，不覆盖现有钩子。

### 11.2 读取内容

接班客户端按顺序读取：

1. 当前项目的 `当前接力.md`；
2. 当前项目最新有效日报；
3. 全局总览中的全局拍板和跨项目待办。

它不读取其他项目的详细日报和原文。没有项目时读取“综合临时”的当前接力。

### 11.3 启动补齐

客户端发现源会话比项目日报新时，先执行目标项目的增量采集和摘要，最长等待 300 秒。补齐失败时，它读取上一份有效接力并明确输出“最新内容尚未归纳”。该轮不能标记为最新闭环。

### 11.4 读取回执

读取成功后，客户端写入：

```text
~/.local/state/ai-session-sync/read-receipts.jsonl
```

每条回执包含平台、主会话 ID、项目 ID、接力哈希、日报哈希、读取时间和新旧状态。回执不包含正文。

## 12. 调度与时效

系统使用变更驱动与固定兜底两套机制：

- `collect` 每 5 分钟扫描活动主会话；
- 项目材料变化后，等待连续 3 分钟无新消息，再触发项目摘要；
- 同一项目 15 分钟内最多调用一次 Hermes；
- 05:50、11:50、17:50 和 23:50 保留全量落后检查；
- 接班客户端在读取前执行目标项目补齐检查；
- Vault 写入后唤醒现有发布任务，不建立第二套 Git 提交器；
- Mac 睡眠后，下一轮按状态指纹补齐，不依赖错过的定时点。

没有材料变化时不调用 Hermes。活动会话持续写入时，系统依靠消息指纹增量更新，不重复摘要未变化的项目。

## 13. 八阶段回执与闭环状态

每轮内容使用 `cycle_id` 和 SHA-256 哈希串联以下阶段：

1. `collected`：主会话消息已接受；
2. `sanitized`：脱敏与独立复检通过；
3. `classified`：项目和内容类型已确定；
4. `archived`：受管原文已原子写入；
5. `digested`：项目日报和当前接力已验证；
6. `published`：Vault 提交已推送，记录 Git 提交哈希；
7. `consumed`：新主会话已读取该接力哈希；
8. `feedback_archived`：该新会话产生的反馈已再次归档，并携带父接力哈希。

状态器只在八个阶段全部成功时显示“已闭环”。项目状态包括：

- `已闭环`：八阶段齐全；
- `等待接班`：已发布，尚无新会话读取；
- `本地完成，云端待推送`：发布未完成；
- `摘要待补跑`：Hermes 未完成；
- `安全隔离`：复检阻断；
- `闭环中断`：连续失败达到阈值。

状态器提供 `ai-session-sync status` 命令，并生成：

```text
20-AI复核/全局/闭环状态.md
```

状态页只含项目、阶段、时间和哈希短码，不含私密正文。

## 14. 失败与恢复

- 源文件未写完或单行损坏：记录文件与行号，不推进对应消息游标；下轮重试。
- 子代理或平台内部内容：记录跳过计数，不归档，不视为失败。
- 脱敏或复检失败：立即隔离；该消息不进入 Hermes、Vault 和 Git。
- 分类置信度不足：进入临时队列；不混入已有项目接力。
- 项目注册表损坏：保留上一版，停止自动建项，返回失败。
- Hermes 离线或输出无效：保留原文和上一版接力，不推进摘要回执。
- Vault 写入失败：保留旧文件，不推进归档或摘要状态。
- Git 拉取或推送失败：保留本地提交，发布回执保持未完成，网络恢复后重试。
- 接班读取失败：不写读取回执，新会话必须提示接班失败。
- 任一分阶段失败：命令返回非零退出码。

同一阶段连续失败三次后发送 macOS 本地通知。安全隔离立即通知。Server酱告警只发送项目 ID、阶段和错误类别，不发送会话正文、路径、金额或凭证片段。

## 15. 状态与幂等

运行状态继续保存于：

```text
~/.local/state/ai-session-sync/
```

状态至少记录：

- 源文件身份、平台、大小、修改时间和主会话判定；
- 已接受消息指纹和消息分类指纹；
- 脱敏、分类、摘要策略版本；
- 原文、项目日报、当前接力和全局总览指纹；
- 八阶段回执、父接力哈希和最后成功时间；
- 发布提交哈希、读取回执游标和失败计数。

策略版本变化时，系统只重算受影响阶段。第二次运行不得产生重复消息、重复项目、重复回执、无意义文件修改或空 Git 提交。`--dry-run` 只向标准输出报告计划，不创建锁、日志、状态、隔离文件或 Vault 文件。

## 16. 迁移方案

迁移必须可恢复，按以下顺序执行：

1. 备份当前运行状态、受管 Vault 目录和 launchd 配置；
2. 暂停旧 AI 会话采集与摘要任务；
3. 将已归档的 Codex 子代理、非主会话和受污染日报移到本机可恢复隔离目录；
4. 使用新安全策略扫描 Vault 当前内容和 Git 历史；
5. 若发现真实凭证，停止迁移并要求轮换；未发现则继续；
6. 从原始 Codex、Claude 会话重新生成脱敏原文、分类索引和项目资料；
7. 在临时 Vault 运行幂等和故障演练；
8. 安全合并 `codex/ai-session-sync` 与 `main`，处理旧 `obsidian_sync*` 的重叠职责；
9. 运行专项测试和 screener 全套测试；
10. 推送 `main`，安装提交版本，核对运行副本与主线 SHA-256；
11. 加载新任务和全局接班指令，完成真实双向接力；
12. 确认 Vault 与源码仓本地 `main` 都和远端一致。

迁移不直接永久删除旧产物。确认新闭环通过验收后，用户可另行决定隔离备份的保留期限。

## 17. 测试策略

### 17.1 单元测试

至少覆盖：

- Codex、Claude 主会话识别和子代理排除；
- 平台动态 `user` 包络、工具块、思考块和附件排除；
- 消息分段、跨日和多项目分类；
- Git 根、别名、Hermes 分类和低置信度临时路由；
- 新项目创建、别名合并和防碎片条件；
- S0、S1、S2、S3 四级处理；
- Server酱 SendKey、Webhook、Cookie、私钥、高熵串和身份信息；
- 金额区间、同币种比例、跨币种禁止猜测和数量隐藏；
- 独立复检阻断与隔离日志零泄漏；
- 原子写、状态顺序、策略升级和重复运行零差异；
- 项目日报、当前接力、全局总览和来源链接校验；
- 八阶段回执、父哈希、状态判定和非零退出码。

### 17.2 集成测试

在临时会话目录、临时 Vault 和模拟 Hermes 上验证：

- 多项目、多主题和新项目自动分类；
- Hermes 离线不阻断原文；
- Git 离线保留发布欠账并在恢复后补齐；
- 接班启动补齐、旧接力降级和读取回执；
- 活动会话增量、Mac 睡眠补跑和并发锁；
- 安装器只更新受管指令块，不覆盖用户配置。

### 17.3 真实端到端验收

真实验收必须完成两个方向：

1. Codex 完成一项带明确拍板和待办的任务；Claude 新主会话自动读取并继续处理。
2. Claude 产生新结论；Codex 新主会话自动读取并准确复述来源、拍板和下一步。

两个方向都必须留下 `consumed` 和 `feedback_archived` 回执。

## 18. 交付验收标准

当且仅当以下条件全部成立，系统才算完成：

1. 回填时仍存在、格式受支持的合格主会话收录率为 100%，已识别 Codex 与 Claude 子代理归档数为 0。
2. 平台动态指令、工具输出、隐藏内容和附件正文归档数为 0。
3. Server酱、API Key、Webhook、Cookie、私钥、身份和精确资金测试均无法进入 Hermes、Vault、日志和 Git。
4. 存量会话全部拥有稳定分类；低置信度内容最终进入明确项目或“综合临时”，没有悬空记录。
5. 同义项目不会分裂；多主题会话能进入多个项目索引且原文只保存一次。
6. 每个活跃项目都有有效日报和当前接力；所有事实均有合法来源链接。
7. 新 Codex 和 Claude 主会话能识别当前项目，只读取该项目资料和允许的全局信息。
8. Codex → Claude → Codex 的真实接力形成完整八阶段哈希链。
9. Hermes、Git 和网络故障演练都能自动恢复；失败期间不产生伪成功回执。
10. `ai-session-sync status` 与实际文件、Git 提交、读取回执一致。
11. 专项测试和 screener 规定的全部测试通过。
12. 同步源码位于 `main` 并已推送；运行副本与提交版本一致。
13. Vault 本地 `main` 与 `origin/main` 一致；源码仓本地 `main` 与 `origin/main` 一致。
14. 现有 screener 服务、交易规则、生产数据库和交易定时任务未发生未授权改动。

## 19. 上线与回滚

上线分四步：

1. **影子分类**：新分类器只生成临时报告，不改生产 Vault；比对项目归属和脱敏结果。
2. **重建资料**：在临时 Vault 重建全量资料，完成安全扫描和幂等验证。
3. **切换写入**：暂停旧任务，原子替换受管目录，启用新采集、分类、摘要和状态任务。
4. **启用接班**：更新全局受管指令块，完成真实 Codex → Claude → Codex 验收。

回滚时卸载新任务，恢复 launchd 与 Vault 备份，恢复旧状态目录副本，并移除全局受管指令块。原始平台会话从未修改，因此可以重新实施迁移。

## 20. 非目标

本期不做：

- 不保存隐藏推理、系统提示、工具输出和附件正文；
- 不修改或删除 Codex、Claude 原始会话文件；
- 不把摘要注入平台隐藏上下文；
- 不让 Hermes 使用本机工具；
- 不让一个项目自动读取其他项目的详细资料；
- 不依据接力摘要自动执行交易、提交代码或发送外部消息；
- 不承诺清除平台原始会话中已经存在的精确金额或凭证；
- 不建立第二套 Vault Git 提交和推送流程。
