## 1. 结论

**K3 切换未通过。外部配置按失败规则保持 `kimi-k2.6`，生产未切换、未部署、未触发正式生成。**

K3 首轮真实请求成功触发 `$web_search`，但现有 Chat Completions 内建工具回环在第二轮续接时收到 HTTP 400。两段式门禁因此只通过“搜索确证”第一段，没有通过“工具结果续接并生成正文”第二段。系统正确回收到 `skeleton_ready`，没有初稿、没有静默降级，也没有把失败包装为七节校验成功。

K3 官方工具当前要求 Formula API 的工具目录、`tool_call`、fibers 回传与续接协议。现有 K2.6 适配器使用 Chat Completions 的 `builtin_function` 消息回环；它能取得 K3 的首轮搜索结果，却不能完成续接。这是本次失败的根因。

本批只做模型兼容性验证，不实施新的 Formula 适配器。若后续要切 K3，应另开 TDD 批次实现 Formula 协议，并重新做真实搜索、七节规格、等效环境和部署门禁。

## 2. 官方协议核对

核对的官方资料：

- Kimi Chat API：`https://platform.kimi.com/docs/api/chat`
- Kimi 联网搜索：`https://platform.kimi.com/docs/guide/use-web-search`
- Kimi 模型目录：`https://platform.kimi.com/docs/models`
- K3 官方工具 / Formula：`https://platform.kimi.com/docs/guide/use-official-tools`

官方 Chat API 声明 `tool_choice` 支持 `auto`、`none` 和 `required`。真实最小请求也证明 `kimi-k3 + $web_search + tool_choice=required` 被接受：HTTP 2xx、`finish_reason=tool_calls`、返回工具为 `$web_search`。

本批**不启用** `required`，理由有二：

1. 它只硬化首轮必须调用工具，不能修复第二轮 HTTP 400；
2. 若原样用于成稿轮，会继续强制工具调用，不符合“搜索后生成正文”的两段状态机。

后续 Formula 适配器可在“搜索确证”轮使用 `required`，在有 fibers 结果后的成稿轮切回允许输出正文的选择策略。该改动必须有独立测试和等效验收，不能在模型探针里顺手修改生产路径。

## 5. 调试复现与根因

为避免猜测，本批只做了三个单变量最小复现，每次首轮均真实触发 `$web_search`：

| 变体 | 首轮 | 续接 | 耗时 |
| --- | --- | --- | ---: |
| 保留 assistant 空 `content` | 2xx / `$web_search` | HTTP 400 | 1.964 秒 |
| 工具结果作为最后一条消息，不追加成稿指令 | 2xx / `$web_search` | HTTP 400 | 2.598 秒 |
| 原样回传工具参数字符串 | 2xx / `$web_search` | HTTP 400 | 4.471 秒 |

三次都失败后停止排列组合。官方 K3 工具文档给出的工作链是 Formula API：先取工具目录，模型返回工具调用，再向 fibers 接口提交结果，最后续接模型。现有 Chat Completions 回环不是这条协议。证据支持“协议不兼容”，不支持“密钥问题”“搜索没发生”或“Prompt 问题”。

## 7. 与 K2.6 稿的质量差异

K3 没有生成正文，因此**无法做稿件质量比较，也不选优胜模型**。

可客观列出的 K2.6 已验收稿指标为：七节齐全、核心股 5 只、正文非空白字符 4814、来源链接 6 个，其中带日期 HTTPS 来源 5 个；“数据骨架未提供”诚实标记出现 17 次。上轮证据没有记录 K2.6 耗时和 token，本报告不作倒推。
