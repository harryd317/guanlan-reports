# 全局 AI 接力闭环交付总结

## 当前结论

全局接力功能已在 `codex/global-ai-handoff-loop` 完成，源码、隔离端到端和真实只读影子演练均通过。系统能把 Codex 与 Claude 主会话中的用户可见文字自动脱敏、分类、归档和摘要，并用八阶段哈希回执验证 Codex → Claude → Codex 的接班与反馈父链。

生产迁移没有启用。2026-07-22 的正式安全门仍发现凭证类内容，因此程序按设计停在 `migrate plan`：没有写正式 Vault、全局 Codex/Claude 指令、LaunchAgent、运行状态或回滚备份，也没有重启股票服务、修改交易规则、数据库和调度。功能可用性已经实现；正式上线只差外部凭证轮换/清理后重新通过安全门。

## 已实现的闭环

1. 只读取 Codex、Claude 顶层主会话的用户可见文字，排除系统指令、隐藏推理、工具流、附件和子代理内容。
2. 在任何分类、Hermes 或 Vault 写入前执行 S0~S3 脱敏和独立复检；阻断项只留下本机元数据隔离记录。
3. 规则优先、Hermes 兜底地自动归类项目；低置信度内容进入临时队列，不污染已有项目。
4. 每段脱敏原文只保存一份，项目和日期资料只用锚点链接；生成项目日报、滚动接力和安全全局总览。
5. `ai-session-sync` 按变化运行、限频、补跑和恢复；Mac 睡眠或 Hermes/网络故障后按指纹补齐。
6. Codex 用权威任务 ID，Claude 用受管 `SessionStart` hook 绑定身份；读取前补齐，失败时诚实回退上一份有效接力。
7. 现有 `com.harryd317.screener-vault-sync` 是唯一 Git 发布器；只有远端对齐并验证 Git blob 后才写发布回执。
8. `collected → sanitized → classified → archived → digested → published → consumed → feedback_archived` 八个回执以 `cycle_id` 和 SHA-256 父链相连；缺一阶段就不显示“已闭环”。

接力资料只提供上下文，绝不自动授权交易、修改代码或发送外部消息。

## 运维界面

正式启用后使用：

```bash
ai-session-sync run
ai-session-sync catch-up --project <project-id>
ai-session-sync status
ai-session-handoff read --platform codex --session-id "$CODEX_THREAD_ID" --cwd "$PWD"
ai-session-handoff read --platform claude --cwd "$PWD"
```

六种状态为：`已闭环`、`等待接班`、`本地完成，云端待推送`、`摘要待补跑`、`安全隔离`、`闭环中断`。生产任务目标标签为 `com.harryd317.ai-session-sync` 和 `com.harryd317.ai-session-fallback`；状态目标根为 `~/.local/state/ai-session-sync`，Vault 目标根为 `~/obsidian-knowledge-base`。

迁移顺序固定为扫描、暂存、激活：

```bash
ai-session-sync migrate plan --since 2026-06-20
ai-session-sync migrate stage --since 2026-06-20 --staging-vault <私有临时目录>
ai-session-sync migrate activate --manifest <暂存清单> --confirm <确认令牌>
ai-session-sync migrate rollback --manifest <备份清单> --confirm <确认令牌>
```

只有 `plan` 返回 0 才能继续。激活会在两个独立私有位置生成认证备份，清单记录文件哈希、任务快照和恢复状态；任一副本仍可驱动幂等回滚。当前未激活，所以没有可填写的生产回滚清单路径。

## 安全门结果

`migrate plan` 返回非零，`safe_to_activate=false`。扫描覆盖 774 个唯一 Git blob、208 个修订；当前文件有 76 个阻断引用，历史唯一 blob 上下文有 185 个阻断项，类别限于授权令牌、命名凭证、服务密钥、会话密钥、提供商密钥和 webhook。交付记录只保存类别与数量，不保存命中文本、完整路径或凭证片段。

因此没有执行 `stage`、`activate`、安装、全局指令合并、LaunchAgent 切换、正式回填、真实接班验收、合并或推送。恢复上线的前置条件是轮换或移除这些凭证，让同一 `migrate plan` 返回 0。
