## 1. T1 · 熔断容量公式(最小件,先行)

- **params.py**:PARAM_META 新增 `LADDER_COST_CAP_PCT`(默认5,position组,"阶梯账本总成本仓位上限%")、`LADDER_DD_BUDGET_PCT`(默认4,position组,"阶梯预计回吐占权益上限%,=解锁仓市值×30%")。不入 FROZEN_KEYS。
- **新模块 ladder_lib.py**:纯函数 `capacity_check(entries, equity, cost_cap_pct, dd_budget_pct) -> {"ok","cost_pct","dd_pct","verdict_text"}`;entries=[{cost, mkt_value}];预计回吐=mkt_value×30% 合计/equity。零 IO,可独测。
- **service.py**:`/api/overview` 响应新增 `ladder_capacity` 键(现值恒 0/上限/未启用标记;equity 复用现有权益计算);**只加键不改既有键**(overview 既有断言不许动)。
- **trade.html**:账户分区尾部两条预算条(0%/5%、0%/4%)+「阶梯未启用 · 10-09评审」灰tag,样式对齐原型屏3。
- 测试 TPL-A:纯函数边界(0仓/超5%/回吐超4%/两者同超)、overview 新键形状、旧键回归。

## 2. T2 · 影子阶梯台账(依赖 T1 的 capacity_check)

- **storage.py**:建表 `ladder_shadow`(id, code, name, entry_date, entry_price, unlock_date, unlock_close, unlock_gain_pct, peak_close, variants_json, capacity_json, status[tracking|closed], created, updated;CREATE TABLE IF NOT EXISTS 风格)。
- **新模块 ladder_shadow.py**:
  - `detect_unlocks(positions, closes)`:纪律仓(strategy≠manual)收盘浮盈首次≥+50% 且无 open 行 → 登记(记 capacity_check 当时判定快照);
  - `advance_daily(fetch=get_hist2 可注入)`:对每条 tracking 行按收盘推进三变体:
    ①`base` 现行规则=镜像真实仓(真实出场日记实际结局);
    ②`keep13_weekly` 部分留仓⅓:真实出场时 2/3 按实际出场价计,剩 1/3 继续,**收盘跌破30周MA**(周线=ISO周重采样日线收盘,复用 chart 周K逻辑口径)才平;
    ③`full_dd30` 满余仓对照:解锁日起,收盘 ≤ 解锁后最高收盘×0.70 平;
    全部收盘口径;数据拉取失败当日跳过留痕不炸;
  - 幂等:同日重跑不重复登记/推进(updated 日期守卫)。
- **EOD 编排层挂点**:扫描落库后调用(与 notify_gate_open 同位置同防护)。
- **service.py**:`GET /api/ladder_shadow`(空态含历史参考文案数据;行含三变体现状+容量判定chip);
- **strategy.html**:P4 影子日志卡下方新增「阶梯影子台账」卡(空态文案/表格/口径说明,照抄原型屏1;**累计<20次解锁不出任何比较性结论**——只列事实行,前端不渲染汇总优劣)。
- 测试 TPL-B:解锁检测(49.9%不触发/50%触发/manual不触发/重复不登记)、三变体推进各自出场路径(fixture价格路径)、真实出场镜像、幂等、golden master 零差异、API形状。

## 3. T3 · 重申卡闸门(依赖 T2 的假想推进器,用于影子对照仓)

- **storage.py**:建表 `falsify_conditions`(code, seq, text, status[active|dead], source[ai|user], created, updated, edit_log)与 `override_shadow`(id, code, qty, sell_date, sell_price, rule_exit_date, rule_exit_price, diff_pct, status[tracking|closed], created, updated)。
- **reviewer.py**:`draft_falsify_conditions(code)`——从论点档案(thesis)+个股概况生成3条可判伪条件(接口失败返回 None 不阻塞);买入记账后**后台线程**调用(_spawn_thesis 先例),失败=条件缺席,首次触发重申卡时走"补注册"。
- **service.py** 闸门三端点:
  - `GET /api/reaffirm/{code}`:卡数据=预注册条件(缺席→现场草拟或人工补录入口)+机械facts(浮盈/距周线出场线/本轮回撤/该票历史-20%级次数)+当前闸门状态机状态;
  - `POST /api/reaffirm/act`:body {code, action}:
    `submit_check`(勾选结果;盘中拒绝——15:00 前返回人话"盘中锁定";勾中任一条且属实→开卖出通道当日有效;零勾选→返回"论点未死"文案+两按钮语义)、
    `insist`(进入隔夜冷却,kv reaffirm_cooldown_{code}={filed_at, opens_at=下一交易日09:30})、
    `confirm_sell`(冷却期满且当日9:30~15:00→放行标记 reaffirm_approved_{code} 当日有效);
  - 状态机全程 events 留痕(code=该票, kind=reaffirm_*)。
- **卖出记账分类**(brief/act sold、mng 已卖出、OCR sold 确认,三入口同一函数):当日快照 pos_alerts/日报 exits 含该 code=规则背书→老路径零变化;否则=override:若有 reaffirm_approved 且在效→标 `reaffirm_sell`;否则标 `override_sell`;**两种都放行**,且自动建 override_shadow 行(用 T2 推进器按现行规则假想跟踪到规则出场,差额只在季度复盘展示,日常UI不弹)。场外仓(manual)不进闸门(纯记账通道,现状不变)。
- **前端**:home mng 抽屉与 trade 持仓行加「想卖?先过重申卡」入口(仅无规则卡背书时出现);重申卡=形态A/B(盘中锁定条/盘后勾选/两按钮/冷却倒计时/次日确认按钮);形态C=卖出确认时的 override 提示条(照原型,不阻塞);买入卡尾部加"已预注册3条证伪条件 查看/修改→"(条件缺席时显示"生成中/点此补录")。
- 测试 TPL-C:分类三分支(规则背书零变化断言/approved/override)、盘中锁定、冷却时点(隔夜+非交易日顺延)、零勾选文案、影子对照仓建行与推进、场外仓不受闸、买入老路径回归、golden master 零差异。
