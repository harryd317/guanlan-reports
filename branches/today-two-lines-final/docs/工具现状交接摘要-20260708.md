## 一、这是什么

**A股纪律投研台(一人版投研所)**,跑在本人 MacBook 上的本地服务:
每个交易日收盘后自动筛选中线信号 → 维护"严选池" → 事件级跟踪 → 生成大白话日报,
AI(OpenAI gpt-5.5)负责立项研究/事件解读/复核二审/教学课文,人只负责照卡买卖。

- 技术栈:Python 3.11 + FastAPI + APScheduler + SQLite(screener.db),前端原生 JS 单文件页面(无构建链)
- 服务只绑 `127.0.0.1:8787`,由 launchd 守护(`com.rui.stock-screener.web`,KeepAlive)托管,**勿手动 nohup**
- 数据主源 Tushare Pro(token 在 `.token`),东财(akshare)/新浪为逐级备份;AI key 在 `.env`(均 600 权限,永不进日志/前端)
- 总指令 = `docs/开发指令v3.md`;当前进度:v3 任务 1~8 已交付

## 三、自动化闭环(2026-07-08 任务8 刚修好,当天真实验收通过)

此前用户主诉「更新了也不是当天的数据」,根因五层叠加,现已全部修复:

1. **定时点 16:30**(原 15:20;Tushare 日线收盘后 15~16 点才入库,跑早必拿上一交易日)
2. **新鲜度守门**:`eod.run_eod_scan(expected_date)` —— 全市场最新K线早于"应有最新交易日"
   (`data.expected_trade_date()`:交易日过 15:05 → 今天)即中止不落库,绝不覆盖历史快照
3. **哨兵** `service._catchup_job`:每 30 分钟+启动后 90 秒,交易日 16:30 后发现今天没快照
   (睡眠错过/守门拦下/服务重启)→ 自动补跑
4. **launchd 日历触发**双保险:`com.rui.stock-screener.eod` 周一~五 16:30 调
   `run_eod_trigger.sh` → `POST /api/eod_trigger`(带交易日闸门);Mac 睡眠错过后唤醒补跑
   (注意:plist 的 StartCalendarInterval 多时段必须 1 个 key + array,重复键会被折叠——踩过坑)
5. **前端自报家丑**:`/api/brief` 带 `today/is_stale`,过期时首页黄条「数据截至X月X日」+「立即更新」按钮

验收实录:07-08 17:42 重启 → 17:43:56 哨兵自动开火 → 17:48:35 拿到当天(07-08)快照,
历史快照零覆盖。长效验证口径:连续 3 个交易日不碰电脑,17:00 前首页 date=当天、无黄条。

## 四、代码地图(核心模块)

```
service.py  (~1400行)  FastAPI 入口+全部 API+调度(16:30 定时/哨兵/周报)
eod.py      (~850行)   收盘扫描流水线:取数→规则→池同步→事件→自动研究→日报→推送
data.py     (~760行)   数据源封装:Tushare 主源+备份链、交易日历、expected_trade_date
screener.py            短线规则引擎 v0.1(analyze/check_positions 判定语义是红线,一行不许改)
rules_mid.py           中线规则引擎 v0.2(主模式;analyze_mid/check_exit_mid 同为红线)
brief.py               决定性翻译层:规则输出→大白话消息卡(纯函数,数字只搬运不生成)
reviewer.py (~960行)   AI 层:多引擎(openai/openrouter/deepseek/智谱)、二审、立项、课文
storage.py             SQLite 全部读写(snapshots/pool/thesis/events/daily_reports/ai_usage/lessons…)
daily.py / push.py / intraday.py / params.py   日报组装 / 微信推送(未配置) / 盘中监控 / 参数治理
static/home.html ask.html index.html trade.html settings.html …   前端单文件页
test_rules.py(8) test_rules_mid.py(16) test_web.py(310)   三套测试
```
