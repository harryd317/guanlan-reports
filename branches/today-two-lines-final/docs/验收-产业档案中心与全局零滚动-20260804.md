## 生产等效环境验收

- 启动方式：生产 LaunchAgent plist 克隆副本，同一 `start.sh`、同一静态文件服务方式，独立端口 `18788`。
- 隔离：原生产 plist 一字未改；`screener.db`、`market.db`、`industry_thermometer_sidecar.db`、`S8_research.db` 均使用 SQLite 一致性快照并设为 `0444`。
- 健康检查：`ok=true`，启动指纹与磁盘指纹一致。
- 根 HTML 响应头：`Cache-Control: no-store`，用于防止部署后浏览器复用旧 SPA 外壳。
- 全局零滚动：10 个路由 × 2 个视口 = 20/20 通过。每项均满足页面级 `scrollHeight === clientHeight`，浏览器控制台零错误。

## 首次部署异常与回滚

1. 首次重启后健康检查通过，数据库哈希不变；但生产浏览器首次打开复用了旧 HTML 外壳，今天页实测 `clientHeight=840`、`scrollHeight=849`、`overflow-y=auto`，验收失败。
2. 服务器直读响应体 SHA-256 与新 `static/home.html` 一致，而响应头只有 ETag/Last-Modified，因此根因确认为“浏览器旧 SPA 外壳缓存”，不是模板、静态文件路径或数据库异常。
3. 按门禁立即将生产工作目录精确恢复到上一部署提交 `f7134ed`并重启；`static/home.html` 与 `service.py` 均和该提交逐字节一致，生产健康正常。
4. 稳定失败测试先锁定根 HTML 必须禁止旧壳复用，再做最小修复：只给 `/` 返回的 `FileResponse` 增加 `Cache-Control: no-store`。修复后全量回归、第二轮等效 20/20 零滚动矩阵、8 张截图和哈希复核全部通过。
