# 交付总结 11e:拒绝行为落库(2026-07-09)

## 修的是什么问题(体检 high 级)

用户在首页点「这次不买」「看过了」,此前**只写浏览器 localStorage**——换台电脑、
换个浏览器、清一次缓存,这些行为就彻底蒸发。后果:纪律系统最核心的 KPI
**执行率(系统建议 vs 用户实际执行)永远算不出分母**,"跳过的买入卡后来涨了多少"
这类最值钱的反事实复盘也无从谈起。

## 做了什么

1. **新表 `user_actions`**:记录 日报日期 / 股票代码 / 动作(skip=这次不买、
   ack=看过了、dismiss)/ 卡类型(buy/sell/review…)/ 时间戳;
2. **接口分支**:`/api/brief/act` 新增留痕分支——只记录、不改任何状态,放在
   池查找之前(已移出的票也能记);缺日期时用上海时区今日兜底;
3. **前端一行接线**:本地隐藏行为照旧秒响应,同时静默 POST 落库——
   网络失败绝不阻拦本地隐藏(fire-and-forget),界面零变化;
4. 查询侧给了 `user_action_list(trade_date=None)`,后续绩效页直接取用。

## 这组数据将来能回答什么

- 执行率:系统发了 N 张买入/卖出卡,用户照做了几张?(纪律系统的自我度量)
- 反事实:被跳过的买入卡,20 日后平均涨跌多少?(用户的直觉比系统好还是差?)
- 疲劳度:review 卡被"看过了"的比例——降噪是否到位的量化依据。
