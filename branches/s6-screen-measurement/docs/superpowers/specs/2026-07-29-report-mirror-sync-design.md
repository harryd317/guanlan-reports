# 公开报告镜像同步设计

日期：2026-07-29

## 目标

把源仓库中的 `docs/` 与 `reports/` 交付物同步到独立公开镜像，同时保证策略代码、配置和运行数据不会进入镜像。镜像只保留这两个顶层目录。

## 固定策略

- 仅遍历 `docs/` 和 `reports/`，不从源仓库复制其他路径。
- 排除两张含账户金额的手机截图、所有 `.DS_Store` 和备份文件。
- 只允许文档、网页原型、图片、PDF，以及位于 `reports/` 的报告型 CSV/JSON；拒绝代码、配置、数据库、模型和日志文件。
- 在临时镜像副本内把本机用户目录前缀统一替换成 `~`，不修改源文件。
- 允许 `127.0.0.1` 与本机端口 URL 原样保留。
- 推送前扫描整个临时镜像：任何与本机已知凭证相同的值，或未批准的高置信度 API key，都会终止同步。
- `sk-xxx` 等明确占位符和已审定的合成测试凭证可以保留。

## 同步过程

1. 克隆公开镜像到一次性临时目录。
2. 清空临时工作树中除 `.git` 外的内容。
3. 按白名单复制 `docs/` 与 `reports/`，执行固定排除和路径脱敏。
4. 验证顶层目录、文件类型、排除规则和凭证门禁。
5. 输出机器可读统计：推送文件数、排除文件数与清单、替换处数。
6. 内容有变化时提交并推送 `main`；无变化时只报告统计。

## 交付流程接入

仓库使用版本化的 `post-commit` 钩子。只有新提交触及 `docs/` 或 `reports/` 时才调用同步脚本。钩子失败会明确告警，但不会伪装成同步成功；操作者可直接重跑同步命令。

同步日志只记录统计和文件相对路径，不记录凭证值。
