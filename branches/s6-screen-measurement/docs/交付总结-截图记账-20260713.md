## 一、关键落地决策(拍板记录)

- **人工确认才落库**:`/api/ocr_trade` 只识别+校验,绝不落库;确认入账唯一通道=`/api/brief/act`(action=bought/sold),熔断/开仓门/行业/仓位四道闸门零绕过。
- **池外票收紧为只读展示不可勾**(相对原型②屏收紧):池外老仓若录入 positions 会被 mid 规则接管+孤儿仓提醒,违背"老账老办法"拍板;补录语义留给第二批持仓核对模式一起设计。
- **持仓核对模式(原型③屏)不在本期**,留第二批。
- **隐私三条**:①图片只在内存 b64→请求,任何路径不落盘(含日志);②错误文本先 `_scrub` 后截断;③响应不回显 b64。两页均有"不留存"隐私提示文案。

## 二、交付内容

- **reviewer.py 视觉通道**:`_ask_openai_compatible` 支持 `images` 参数(base64 列表,非空时 user content 变多模态数组;缺省 None 时与旧行为逐字节一致)。`ocr_trade(images)` 三态协议同 interpret(引擎不可用→None/并发锁忙→busy/成功→page_type+trades),强格式 system prompt(看不清一律 null 严禁猜/只认已成交/持仓页 trades 留空),坏行(方向/6位代码/价格不合格)**丢弃并计数 dropped_n,绝不修补猜测**。视觉引擎=`.env` 的 `AI_VISION_ENGINE`(默认 openai);**生产实际引擎:openai 通道,OPENAI_MODEL=gpt-5.5**。
- **POST /api/ocr_trade**:images 空/超 4 张/单张超 8MB 人话拒绝;逐笔交叉校验三分类——watchlist_buy(等买点票 ✓ 可操作)/holding_sell(持有票卖出 ✓ 可操作)/outside(池外票只读,"老账老办法"文案);价格合理性=昨收±板幅(30/68 开头 ±19.8% 其余 ±9.8%),超带警示、无参考价提示自行核对。
- **首页📷截图填单**(每张价格卡):选图→canvas 压到最长边 1280→识别→命中该票的可操作成交→价格/金额预填+黄底 `.ocrfilled` 标识→仍走原按钮落库;未命中/失败/忙均人话提示。按钮不带 cardbtn 类(自管"识别中…"状态)。
- **交易台批量识别卡**(#ocr-card):多图上传→结果表(方向/股票/价/量/金额/校验列),actionable 行默认勾选、outside 行灰显禁勾;「确认入账 N 笔」逐行串行走 `/api/brief/act`,成功打 ✓、失败显示后端人话(need_force 提示去首页走强确认,批量不做 force)。
