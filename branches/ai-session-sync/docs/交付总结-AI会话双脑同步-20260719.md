## Hermes 安全与日报

Hermes API Server 的 `platform_toolsets.api_server` 已设为空集。每次摘要请求前，同步程序都会读取 `/v1/toolsets`；只要有任意工具集启用就立即拒绝调用。安全回填中的 Hermes 日志均为 `tool_turns=0`。日报必须包含八个固定标题，事实项必须链接当日受管原文；未知文件链接、敏感信息、缺标题或无来源的事实均不落盘。Obsidian 文件内锚点链接会在校验时归一到受管源文件。

首轮日报回填结果为新增 14、跳过 12、格式校验失败 4；失败样本转化为回归测试并修正锚点/包装文字兼容后，定向补跑新增 4、跳过 10、失败 0。最终所有 23 个有原文的日期都有通过校验的日报。

## 恢复与手工运行

停用定时任务（不删除归档）：

```bash
launchctl bootout 'gui/501/com.harryd317.ai-session-collect'
launchctl bootout 'gui/501/com.harryd317.ai-session-digest'
```

重新安装并加载：

```bash
bash install_ai_session_sync.sh
```

手工收集和摘要：

```bash
~/.local/bin/ai-session-sync collect --since 2026-06-20
~/.local/bin/ai-session-sync digest --since 2026-06-20
```

Hermes API Server 的零工具限制位于 `~/.hermes/config.yaml` 的 `platform_toolsets.api_server: []`。如未来要恢复 API Server 工具，应先停用摘要 LaunchAgent，再单独评估权限；否则摘要预检会按设计拒绝运行。

## 已知边界

- 原文归档保留受管主会话的完整脱敏可见文字；单个会话源超过 60,000 字符时，Hermes 的当次摘要材料会截断并添加提示，日报仍链接完整原文。
- Hermes API 请求的脱敏材料和输出会按 Hermes 自身策略留在本地 `state.db`。
- 原文最长有 15 分钟延迟；日报仅在四个固定时点更新。
- Git 发布依赖现有 Vault autosync 的网络和认证；发布失败不会删除本地归档或手动推进同步状态。
