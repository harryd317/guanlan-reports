## 仅允许三项修正

### 1. 实际信号日资格重检

现有引擎在收盘信号日作出交易决定、下一交易日开盘只执行成交适配。为避免读取下一交易日收盘后
才知道的集群状态，资格时点统一锁为实际 `signal_date`；同时记录计划成交日
`planned_entry_date`。每个原始买点仍按既有规则产生，创建订单前按 `signal_date` 重新检查：

1. 质地底线：只使用 `f_ann_date <= signal_date` 的已公开年报；
2. ST：按 `signal_date` 的日级 ST；2016 年前继续使用已声明的曾用名区间辅助；
3. 申万二级：按 `in_date/out_date` 取 `signal_date` 有效成员，缺失即不成交；
4. 集群活性：用 `signal_date` 的有效申万二级和本组既有 `cluster_hits` 档复核，未激活即不成交。

任一项不合格或关键状态缺失，该笔交易不发生。拦截记录必须同时保留 `signal_date`、
`planned_entry_date`、逐项结果、拦截原因、捕获日行业和信号日行业。`601111.SH` 的原始
`signal_date=2022-03-25` 必须出现在拦截名单；其计划成交日为 2022-03-28，原因必须包含
“公告时点质地底线未通过”。评分仍使用原信号既有字段，不重算 RS、距离或权重；实际成交订单的
行业上限使用信号日有效申万二级。

### 2. 账本封存强化

- 新建独立 `S3_v0_2_backtest_runs.db`，不修改或复用 v0.1 作废账本。
- 每次读取存量样本内、锁参、样本外、S2 和报告制品前复验内容哈希及参数一致性。
- `seal_run` 必须从账本内容和登记制品内部计算封存根哈希，禁止调用者随意传入结果哈希。
- 封存后以 SQLite 触发器拒绝相关运行的 INSERT/UPDATE/DELETE；允许只读状态与报告核验。
- 样本内仍恰好 81 行，样本外仍恰好一行；损坏、未知参数、哈希不符或第二次样本外一律停机。

### 3. 8% 熔断恢复代理

- 账户净值相对当前峰值回撤达到 8% 时，记录触发日和触发日净值并停止新仓。
- 后续只靠已有持仓和现金演化；当某个后续交易日收盘净值回升至或高于该次触发日净值时，
  记录恢复日，恢复日之后的下一个交易日才允许新仓。
- 恢复时把回撤基准峰值重置为恢复日净值，避免按旧峰值同日立即再次触发；之后继续按新高更新。
- 以上只有既有 8% 边界，没有新增可调参数。生产环境仍只允许人工恢复，不接入该代理。
- 报告必须列出每次触发日、触发净值、恢复日和恢复净值；2015—2021 分段不得再出现
  2016—2021 连续六年零成交。若仍出现，直接判定 v0.2 验收失败，不修改代理或参数补救。

## 报告与归档

- v0.1 作废报告及 CSV 永久保留，污染标签固定为“信号日资格陈旧污染”，不得覆盖或删除。
- v0.2 使用全新文件名，必须附新旧对照：
  - 被信号日资格重检拦截的原始交易；
  - 因实际行业变化而改变的订单；
  - 因熔断恢复新增的交易；
  - 两个分段及逐年交易数变化；
  - 共同交易的结果差异。
- 广度门方向异常只记入 v0.3 研究清单：门开期间信号 60 日中位收益连年为负。本次不改广度门、
  不新增过滤、不改变任何策略规则。
