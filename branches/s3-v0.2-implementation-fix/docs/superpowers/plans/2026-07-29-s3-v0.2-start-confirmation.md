### 验证设计

1. **信号日资格重检**
   - 夹具分别令质地、ST、成员、集群活性在捕获后失效，四种情况均不得创建订单。
   - 状态缺失按不合格处理；财务断言 `f_ann_date <= signal_date`，成员断言信号日位于
     `in_date/out_date`；次日开盘数据只用于成交适配，不用于集群资格。
   - 冻结真实快照集成验收：`601111.SH / signal_date=2022-03-25 /
     planned_entry_date=2022-03-28` 必须出现在 `blocked_entries`，原因含质地底线；
     v0.2 交易 CSV 中不得存在该键。
   - `002516.SZ`、`002595.SZ`、`601111.SH` 的信号日行业必须等于历史成员表时点值，
     或因其他资格失败进入拦截表，不能沿用旧行业。

2. **熔断恢复代理**
   - 净值刚好到峰值 92% 必须触发；触发日不能同日恢复。
   - 低于触发日净值继续停新仓；后续收盘达到触发日净值记录恢复，下一交易日才恢复订单。
   - 恢复时峰值重置；支持多次触发/恢复，事件次序和金额确定性一致。
   - 全量运行后报告每次触发/恢复；2016—2021 交易数合计必须大于 0，且不得形成六年连续零成交。

3. **账本封存**
   - 运行前后参数网格都为 81 个唯一 ID，网格哈希不变；选择规则边界和一次样本外测试继续通过。
   - 篡改 `result_json`、`result_hash`、`params_json` 任一项后读取必须失败。
   - 封存根由账本内部计算；封存后对样本内、锁参、样本外、S2、制品表的
     INSERT/UPDATE/DELETE 均被 SQLite 拒绝，只读 `status/verify/report` 可用。

4. **新旧对照与范围**
   - v0.2 报告逐笔列出“旧有新无”“旧无新有”“共同但行业/结果改变”，并列出两个分段及逐年交易数。
   - `blocked_entries` 与“资格重检拦截”一致；`circuit_events` 与权益曲线逐日独立复算一致。
   - 报告明确：广度门异常转 v0.3，本次无任何处理。
