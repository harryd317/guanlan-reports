## 修的是什么问题(体检 med 级,但有不可逆性)

系统的中线策略有两类买点:**入场A(突破后浅回踩)**和**入场B(深回调后放量再突破)**。
"哪类入场更赚钱"是这套策略未来最关键的归因分析——但账本(positions/trades 表)里
根本没有信号类型字段,记账时不采集,**等交易攒够了想回头分析时,数据已经补不回来**。
当前生产库恰好 0 笔交易,此刻加字段是零迁移成本的最后窗口。

## 做了什么

1. **schema 增列**:positions 与 trades 各加 `signal_type TEXT` 列
   (`entry_A` / `entry_B` / `manual`);init_db 里做幂等增量迁移
   (老库自动 ALTER 补列,跑多少遍都安全)——这也是本项目第一个 schema 迁移先例。
2. **全链路携带**:
   - 买入落库时自动回填:从当日日报卡反查该票的技术状态(entry_A/entry_B),
     反查不到(手动录入/无卡)一律记 `manual`,绝不猜;
   - 平仓归档(close_position)与落袋减半(add_trade_direct)自动把持仓上的
     信号类型带进交易记录;
   - `list_trades(signal_type=...)` 支持按信号过滤,后续绩效页可直接
     算"entry_A vs entry_B 的胜率/期望"分解。
