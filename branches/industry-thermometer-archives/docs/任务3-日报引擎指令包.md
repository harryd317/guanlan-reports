## 三、v3 日报规格（第六节原文摘要）

### 生成时点
每交易日收盘筛选流水线末端自动生成（15:20）：筛选→事件采集→池状态更新→**日报**→macOS通知"日报已生成:今日待办N件"。提供手动重生成按钮。

### 机械层（每日必产，零API成本，决定性规则生成）

**头部|今日待办**：全池按优先级排序的指令清单，`EXIT/TRIM > ENTER/ENTRY_READY > REVIEW > WATCH临近`，每条一行、可点进个股。首屏必须直接回答"我今天要做什么"；没有待办就大字"今日无操作"。

**逐票卡片（池内每只必有）**：状态徽章 / 收盘与涨跌 / **与关键位的距离**（止损位、周MA30、平台价、减半线，全部带具体价格和百分比）/ 今日事件diff（无则"无"）/ **下一步（必填结构化字段）**：

```python
next_action = {
    "type": "HOLD" | "WATCH" | "ENTRY_READY" | "ENTER" | "TRIM" | "EXIT" | "REVIEW" | "REMOVE",
    "condition": str,      # 具体触发条件，带数字
    "price_level": float | None,  # 关键价位
    "deadline": str | None,       # 期限（如"明日开盘"、"本周五前"、"无"）
}
```

**文风示例（指令单，不是研报）**：
- 「HOLD|无事。止损26.40(-9.2%)，周MA30 27.15(-6.6%)，距减半线还差18%。」
- 「WATCH|等回踩41.0±0.5且当日量<20日均量;满足则次日看止跌阳线。」
- 「EXIT|收盘98.20<周MA30(101.3)，明日开盘执行清仓，依据E2。」
- 「REVIEW|今日公告削弱论点第2条，48小时内复核，周五前给结论。」

**禁模糊词规则（验收硬标准）**：「持续关注」「保持观望」「注意风险」「逢低布局」等**不带数字条件与期限的建议一律违规**。每条建议必须含：具体价位或条件 + 触发后的动作 + 期限。

**尾部**：大盘周线门状态 / 池子概况（各状态数量、今日迁移）/ 风险检查（总仓位、单票集中度、同故事≤2只是否超限）/ 一句免责：建议=系统纪律的输出，终判在人。

### Claude层（仅事件触发，控制成本）

**触发条件**：新公告或业绩披露 / 技术状态迁移（入场信号、破周MA、减半触发）/ 行业指数周线变档 / 入池立项。

**输出**：该事件**验证/削弱/无关**于论点档案哪一条 + 是否改写该票今日 next_action + 三句话内的解读。

**无触发的票，Claude一个字不写。**

**周报**：每周六10:00(Asia/Shanghai)，全池复盘 + 行业仪表盘解读 + 下周关注日历（财报披露日、解禁、已知事件）。

**成本护栏**：所有Claude调用计数落库（ai_usage表，任务2已建），设置页显示当月调用次数与估算费用；无Key时机械层照常运行，Claude层跳过并在日报标注「AI解读未启用」。

### 事项A：机械层 next_action 决策引擎（新文件 daily.py）

新建 `daily.py`——日报的核心模块。**纯函数，不碰网络、不碰引擎**——机械层全部由收盘数据 + 池状态 + 规则引擎输出决定性生成。

```python
# daily.py 核心函数

def compute_next_action(pool_row, tech_result, thesis, events_today):
    """对池内一只票生成 next_action dict。
    
    输入:
    - pool_row: pool 表行 dict（state/stop_price/entry_price/platform_price/...）
    - tech_result: analyze_mid 的返回 dict（state/close/platform/stop/hint/week_ma30/...）
                   或 check_exit_mid 的返回 list（持仓出场）
    - thesis: 论点档案 dict（None 则不引用论点）
    - events_today: 今日事件 list（空则"无"）
    
    输出 next_action dict:
    {
        "type": "HOLD"|"WATCH"|"ENTRY_READY"|"ENTER"|"TRIM"|"EXIT"|"REVIEW"|"REMOVE",
        "condition": str,      # 具体触发条件，带数字
        "price_level": float|None,
        "deadline": str|None,  # "明日开盘"|"本周五前"|"无"
    }
    
    决策逻辑（按优先级，先到先出）:
    
    1. 持仓(holding) + check_exit_mid 返回非空 → EXIT/TRIM
       - EXIT: "收盘X < 止损位Y，明日开盘执行清仓，依据E1/E2/E3"
       - TRIM: "距周MA20乖离+Z%且天量滞涨，明日开盘减半，依据T1"
    
    2. 持仓(holding) + check_exit_mid 返回空 → HOLD
       - "无事。止损X(-Y%)，周MA30 Z(-W%)，距减半线还差V%。"
    
    3. 观察池(watchlist) + entry_A/entry_B → ENTRY_READY
       - "浅回踩到位:止损=平台价X。明日开盘可执行。"
       - "深回调-Z%后再突破:止损=整理区最低收盘X。明日开盘可执行。"
    
    4. 观察池(watchlist) + tracking → WATCH
       - 基于 hint 拆解:
       - "尚未回踩" → "等回踩平台价X±0.5%且当日量<20日均量;满足则次日看止跌阳线。"
       - "回调中(自高点-Y%)" → "等回调到位(20~35%)后看再突破;不到不追。"
    
    5. 候选(candidate) + capture → REVIEW
       - "新候选:创250日新高+RS前15%。需立项研究(72h)或否决。"
    
    6. 候选(candidate) 即将过期(expire_at - today ≤ 2交易日) → REMOVE
       - "候选将于X过期,未立项将自动移出。"
    
    7. 今日有事件(events_today 非空) → type 升级为 REVIEW
       - condition 提及具体事件 + 论点关联
       - "今日公告XXX，48小时内复核，周五前给结论。"
    
    8. 其余 → HOLD "无事。"
    """
```

**关键约束**：
- 每条 next_action 的 condition 必须含**具体数字**（价位、百分比、日期）
- HOLD 也必须带数字（止损位、周MA30、距减半线距离）
- deadline 必须明确（"明日开盘"/"本周五前"/"无"），不能是空
- **生成后自检**：含禁模糊词且无数字条件 → 标红并记日志（见事项E）

### 事项C：Claude层事件解读（daily.py + reviewer.py 扩展）

```python
EVENT_READ_SYSTEM_PROMPT = """你是一人版投研所的事件分析师。
用户池中一只股票今天出了一个事件(公告/业绩/新闻/技术迁移)。
你的任务:判断这个事件验证了还是削弱了当初的入池论点。

输入:事件描述 + 论点档案(七因子记分卡 + 空头报告三路径)。

输出(三句话以内):
1. 结论:验证/削弱/无关——论点第几条?
2. 是否改写该票今日 next_action?(是/否 + 如果是,给出新的指令)
3. 一句话解读。

纪律:①只基于给定的论点+事件推理;②不编造论点里没有的内容;③三句话以内,长度不超过必要。"""


def interpret_event(code, event, thesis):
    """事件解读。调引擎(_ENGINES[ENGINE]),用 EVENT_READ_SYSTEM_PROMPT。
    超时60秒。记 ai_usage(purpose='event_read')。
    引擎不可用时返回 None(日报标注'AI解读未启用',机械层照常)。
    返回 {ok, conclusion, rewrite_action?, note} 或 None。"""
```
