## 2. 措施一 · 阶梯留仓真实执行(核心)

### 2.1 机械口径(与 36 格协议逐字对齐,含合规审钉死项)

- **资格(逐字写死)**:当日出场判定的**首条 EXIT 命中 reason 前缀 == `E3|`**(与 backtest_mid.py:343 回测归因同构——36 格的 105 笔受影响集即"首条命中为 E3"),且 `held_peak/entry_price − 1 ≥ LADDER_QUAL_PCT%`(比较加 1e-9 容差,对齐 ladder_shadow 风格)。**同日 E1+E3 或 E2+E3 双命中、首条非 E3 → 照旧全卖**(回测里这些笔就是全卖,不许样本外扩留仓)。新增钉死用例:同日双命中×2。
- **执行**:够格 → 卖出卡"卖⅓落袋、留⅔继续"(用户可选"不留仓,全部卖出",§4.1);不够格 → 原全卖话术逐字不变。
- **留仓管理**:池行保持 holding + 新字段 `ladder_stage='rump'`、`ladder_start_date=**E3 触发日(EXIT 命中的收盘判定日)**`(不用确认成交日——防用户隔日补确认把峰值窗起点后移、清仓线被静默压低);留仓期出场判定换 **dd25**:峰值=自 ladder_start_date 起最高收盘(qfq 序列每日现算、不落库→免除权折算),收盘 ≤ 峰值×0.75(+1e-9 容差)→ 出清仓卡(reason 前缀 `L1|`),次日执行。
- **T1 减半叠加**:按**当前余额**的⅓/⅔计算(落袋减半已就地减半,自动满足协议"f 作用于减半后的剩余仓")。
- 口径注记(§8 同读):回测=触发日收盘成交,实盘=次日开盘执行,滑点口径与现行 E1~E3 同构。

## 4. 措施三 · 配套(体验审必修,不再是"可选")
