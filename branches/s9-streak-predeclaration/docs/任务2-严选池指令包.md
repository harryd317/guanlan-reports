### v3 规格摘要（第五节 + 第七节）

**状态流**：
```
候选 →（用户点立项）→ 研究中 →（用户点入池/否决）→ 观察池 →（入场信号+用户执行）→ 持仓 →（出场）→ 冷却期（止损后20交易日）→ 移出
```

**池规则**：
- 候选由 capture 信号自动创建，10个交易日无人立项自动过期
- 已在池/冷却中的重复信号只记事件不重复建
- 研究中：自动触发 Claude 立项报告，72小时倒计时，超时日报催办（日报是任务3，本任务只存倒计时字段）
- 观察池+持仓合计 ≤30只；满员时新立项必须先回答"替换谁"
- 入池时刻系统生成**论点档案**

**论点档案**（入池时刻，系统最值钱的动作）：
Claude 按七因子记分卡逐项找证据（带来源链接），**强制输出空头报告——这票失败的三条路径 + 每条路径的可观测信号**。存 thesis 表。此后一切事件解读只回答：**"它验证了还是削弱了当初的入池论点？"**

**事件流**：
events 表，每日采集只针对池内票+当日候选。类型：公告/业绩/新闻/技术迁移/行业变档。按 dedup_hash 去重。个股详情页渲染成时间线。

    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    code          TEXT NOT NULL,           -- 股票代码
    name          TEXT,                    -- 股票名称
    state         TEXT NOT NULL,           -- candidate/research/watchlist/holding/cooldown/removed
    first_seen    TEXT NOT NULL,           -- 首次进候选日期(ISO)
    state_since   TEXT NOT NULL,           -- 进入当前状态的日期(用于过期/倒计时计算)
    expire_at     TEXT,                    -- 候选过期日(candidate 状态: first_seen + 10交易日)
    research_due  TEXT,                    -- 研究中状态的72h倒计时截止时刻
    platform_price REAL,                   -- 突破平台价(止损参考)
    stop_price    REAL,                    -- 当前止损价
    entry_price   REAL,                    -- 实际入场价(holding 状态填)
    entry_date    TEXT,                    -- 实际入场日
    position_amt  REAL,                    -- 持仓金额(元)
    cooldown_until TEXT,                   -- 冷却期截止日(cooldown 状态)
    sort_score    REAL,                    -- 排序分(七因子分×技术状态,池满替换建议用)
    note          TEXT,                    -- 自由备注
    created_at    TEXT NOT NULL,
    updated_at    TEXT NOT NULL,
    UNIQUE(code, state)                    -- 同一票同一状态不重复建(但跨状态可以有多行?不——用一条行+状态变更)
);
-- 实际上同一只票在池子里只有一条行,状态变更就 UPDATE state/state_since。
-- 所以 UNIQUE 约束应该是在 "活跃状态集" 上:一只票不能同时是 candidate 又是 watchlist。
-- 实现:UNIQUE(code) 加一个部分索引,只在 state NOT IN ('removed','cooldown') 时生效。
CREATE UNIQUE INDEX IF NOT EXISTS idx_pool_active ON pool(code) WHERE state NOT IN ('removed');

def _sync_pool(results, trade_date):

    1. capture 状态的票 → pool_upsert_candidate(已在活跃池的不重复建)
