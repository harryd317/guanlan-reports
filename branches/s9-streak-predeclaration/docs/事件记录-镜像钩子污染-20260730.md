# 事件记录：镜像钩子污染

## 摘要

- 发生时间：2026-07-30 22:01—22:05（Asia/Shanghai）
- 影响系统：本地 `screener` Git 主分支及私有远端 `origin/main`
- 数据影响：工作文件、生产数据库、S2/S3/S5 制品和 S6 提交均未损坏
- 外泄影响：无。错误提交被推入既有私有仓库；公开镜像仓库未被本次错误更新
- 恢复结果：本地和私有远端 `main` 均恢复到事故前提交 `b27e3dc`，随后仅以正常后继提交合入修复

## 事件经过

在 `codex/s6-screen-measurement` 工作树提交动工确认文档后，共享 `post-commit` 钩子启动公开报告镜像同步。同步器原计划在临时目录克隆 `guanlan-reports`，写入脱敏后的 `docs/`、`reports/`，再推送公开镜像。

Git 运行钩子时会注入当前仓库的 `GIT_DIR`、`GIT_INDEX_FILE`、`GIT_WORK_TREE` 等环境变量。同步器此前直接复制整个进程环境并传给临时目录中的 Git 子进程，导致临时克隆、提交和推送错误地绑定到源仓库。

事故期间产生了两个不应进入源仓库的镜像提交：

- `a09503e`：`sync: docs and reports from codex/s6-screen-measurement`
- `9137e61`：`sync: docs and reports from main`

其中 `9137e61` 于 22:02:08 被误推到私有 `origin/main`。S6 正常提交 `b148228` 始终保留在 `codex/s6-screen-measurement`，未被覆盖。

## 根因

直接根因是 `scripts/report_mirror_sync.py` 的 Git 子进程环境未隔离：

1. `post-commit` 钩子继承当前工作树的仓库级 Git 环境变量；
2. 同步器的 `_git()` 和 `git archive` 调用原样继承这些变量；
3. `cwd` 虽指向临时镜像目录，但 `GIT_DIR` 等变量优先，Git 实际操作源仓库；
4. 临时镜像的 `commit` 和 `push` 因此改动了源 `main`，并使用源仓库的 `origin`。

既有测试只直接调用同步函数，没有模拟真实钩子环境中的仓库级变量，因此未覆盖该故障路径。

## 影响范围

受影响：

- 本地 `refs/heads/main` 曾从 `b27e3dc` 临时移到 `9137e61`；
- 私有 `refs/remotes/origin/main` 曾从 `b27e3dc` 临时移到 `9137e61`；
- S6 工作树的 `HEAD` 和索引曾短暂指向错误的 `main` 镜像提交。

未受影响：

- 主工作树文件：逐文件 Git blob 校验与 `b27e3dc` 完全一致；
- S6 工作树文件：逐文件 Git blob 校验与 `b148228` 完全一致；
- `codex/s6-screen-measurement` 分支提交；
- 生产服务、生产数据库、S2、S3、S5、T3、T4；
- Git 凭证和敏感信息；
- 公开 `guanlan-reports` 远端。

## 恢复过程

1. 立即停止新的提交和同步操作；
2. 用 `git ls-tree`、`git hash-object` 逐文件核对：
   - 主工作树对 `b27e3dc`：零缺失、零变化；
   - S6 工作树对 `b148228`：零缺失、零变化；
3. 将 S6 工作树 `HEAD` 恢复到 `refs/heads/codex/s6-screen-measurement`，只重建索引，不覆盖工作文件；
4. 使用带旧值保护的 `git update-ref` 将本地 `main` 从 `9137e61` 恢复为 `b27e3dc`；
5. 使用精确租约：
   `--force-with-lease=refs/heads/main:9137e61`
   将私有 `origin/main` 恢复到 `b27e3dc`；远端若出现任何并发更新，命令会拒绝执行；
6. 用 `git ls-remote origin refs/heads/main` 复核，远端返回完整哈希
   `b27e3dc8c1654f237be8a3a552ee772142484f0b`；
7. 本地两个工作树均恢复为干净状态。

## 修复与防复发

修复提交：`f8b9784 fix: isolate report mirror git environment`

修复内容：

- 新增统一 `_git_environment()`；
- 在同步器执行任何 Git 子进程前，删除 Git 报告的仓库级环境变量，包括 `GIT_DIR`、`GIT_INDEX_FILE`、`GIT_WORK_TREE`、`GIT_COMMON_DIR`、`GIT_OBJECT_DIRECTORY` 等；
- `_git()` 和独立的 `git archive` 调用统一使用隔离环境；
- 保留 `GIT_TERMINAL_PROMPT=0`，避免无人值守同步等待交互。

新增真实回归测试：

- 在临时源仓库中显式污染 `GIT_DIR`、`GIT_INDEX_FILE`、`GIT_WORK_TREE`；
- 执行一次完整镜像克隆、提交和推送；
- 断言源仓库 `HEAD` 与已跟踪文件零变化；
- 断言目标镜像远端收到正确的公开文件。

验证结果：

- 修复前：回归用例稳定复现“临时克隆错误绑定源仓库”；
- 修复后：回归用例通过；
- `test_report_mirror_sync`：22/22 通过；
- 修复以快进方式合入本地 `main`，事故前提交 `b27e3dc` 仍是其直接祖先，既有历史未改写。
