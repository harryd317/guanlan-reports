# 公开报告镜像分支覆盖设计

日期：2026-07-30

## 目标

扩展现有公开报告镜像，使每个 `codex/` 分支的已提交 `docs/` 和 `reports/` 都有独立快照。保留现有脱敏、排除和凭证门禁，不修改策略代码、研究数据、回测账本或封存制品。

## 目录映射

- `main` 的交付物继续写入镜像根目录的 `docs/` 和 `reports/`。
- `codex/<name>` 的交付物写入 `branches/<name>/docs/` 和 `branches/<name>/reports/`。
- 其他分支不进入公开镜像。
- 分支同步只读取指定提交，不读取工作树中的未提交文件。

`<name>` 必须是安全的相对路径。当前分支名均为单层名称；若未来出现嵌套名称，脚本把 `/` 编码为 `__`，防止目录歧义。

## 同步边界

每个分支先导出到临时目录，再复用既有构建器：

1. 只导出该提交中的 `docs/` 和 `reports/`。
2. 应用原有文件白名单、永久排除、备份排除和用户目录脱敏。
3. 在独立暂存树执行文件类型、私有路径和凭证检查。
4. 更新镜像中的单个目标目录，不清空根目录或其他分支目录。
5. 对更新后的完整镜像再次执行结构与凭证检查。

分支副本沿用根目录的合成测试凭证批准。门禁比较时先去掉 `branches/<name>/` 前缀，避免同一份已批准文档因镜像位置不同而被误判。

## 自动同步

所有工作树共用主仓库的版本化 `.githooks/post-commit`：

- 钩子从 Git 公共目录定位主仓库中的同步脚本；
- 钩子把当前工作树作为源仓库，只在新提交触及 `docs/` 或 `reports/` 时运行；
- `main` 更新镜像根目录，`codex/` 分支更新对应 `branches/<name>/`；
- 钩子失败输出告警，不伪装成功，也不回滚本地提交。

仓库级 `core.hooksPath` 使用主仓库 `.githooks` 的绝对路径。退役分支无需新增提交，分支指针和制品哈希保持不变。

## 存量回填

批量命令枚举 `refs/heads/codex/*`，按提交导出并构建全部分支快照。它只克隆镜像一次，完成全部本地门禁后生成一个镜像提交并推送，避免多个分支并行推送造成非快进或目录覆盖。

回填结果必须列出：

- 源分支、源提交和镜像目标目录；
- 每个分支的复制数、排除数、替换数；
- 完整镜像的阻断项数量；
- 镜像提交和推送状态。

## 验收

1. 当前全部 `codex/` 分支都存在对应 `branches/<name>/`。
2. `s5-breadth-etf-backtest`、`s3-v0.2-implementation-fix`、`s3-v0.3-structural-fix`、`s3-stage2-backtest` 的 `docs/` 和 `reports/` 与各自提交按同一策略构建的结果逐文件一致。
3. 镜像不含 `.env`、代码、配置、数据库、日志、备份、封存研究库或未批准凭证。
4. 源仓库私有用户目录前缀在镜像中全部替换为 `~`。
5. 四个重点分支的提交指针和封存制品哈希在同步前后不变。
6. 从任一 `codex/` 工作树提交新的交付文档时，钩子只更新该分支目录。
