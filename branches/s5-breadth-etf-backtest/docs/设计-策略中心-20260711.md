> 状态：三节设计已经用户逐节拍板（2026-07-11）。本文档是实现计划的唯一依据。
> 前置阅读：docs/同步Hermes-总览-20260711.md §三（操盘手三路审计）、CLAUDE.md 红线。
> 本设计经四视角对抗审查（量化方法论/工程红线/数据可行性/纪律冲突，42 条缺陷，16 critical），

## 0. 一句话

把"策略"从硬编码升级为插件，把"市况"从二元开仓门升级为多因子识别引擎，
让系统按市况选用有回测背书的最优策略——**每一步升级都踩在证据上，
上层永远压住下层：账户风控 > 策略调度 > 策略插件 > 市况识别 > 数据。**

## 1. 背景与已拍板决策

### 1.1 用户愿景

根据市场整体行情、资金动向、市场热点等因素选择最优策略；策略不止一个（长线+短线）；
自动切换到当前市况下最好的策略。

### 1.2 四个核心决策（用户 2026-07-11 拍板）

| # | 决策点 | 拍板结果 |
|---|--------|----------|
| 1 | 核心动机 | **市况自适应**：降低对单一行情的依赖（审计实锤：87.7% 利润来自 2025） |
| 2 | 策略来源 | 不设限，哪个好用哪个（经审查砍成两路半，见 §8） |
| 3 | 切换机制 | **全自动为终点，硬前提=同类市况下有回测背书**；不搞数月影子期 |
| 4 | 运行结构 | **互斥制**：一时一主策略；已持仓按建仓时策略规则管到平仓 |

附加约定："实时" = **每日收盘（EOD 16:30）判定**，盘中不切（铁律 6：判定只认收盘数据；
盘中切换不可回测）。

### 1.3 方案选择

三方案（全愿景直上 / 纪律版 / 最小观察版）中用户选定**方案二：纪律版**——
全部愿景保留，按证据链排序：P0 账户风控 → P1 策略抽象 → P2 市况仪表盘（只展示）→
P3 背书报告+整机回测 → P4 切换器（10-09 评审后，建议卡起步→达标升全自动）→ P5 策略生产线。

**P4 冻结到 10 月不是延期而是关键路径**：P2 市况引擎上线后需要约 2~3 个月纯展示期
验证判得准不准（按 P0~P2 工期推算，P2 约 8 月初上线，至评审日可攒约 2 个月实绩），
P3 报告 9 月产出，与 2026-10-09 参数解冻评审天然对齐。

### 1.4 明确砍掉/降级的东西（附理由）

- **北向单日净买入因子**：2024-08 起停止披露，数据已死。若要外资视角只剩
  沪深港通成交总额（无方向，仅活跃度）与两融余额（积分档需实测）。
- **板块资金流因子**：无 5 年历史不可回填 + 东财 push2 无契约接口 + 项目有 IP 封禁前科。
  降级为 /strategy 页纯展示（拉得到就显示，拉不到空着），永不进 regime 评分。
- **隔夜外盘/A50 因子**：对 16:30 EOD 判定边际信息≈0（当日 A 股走势已内生化隔夜信息），
  还带来日历错位/数据源不稳三重坑。一行不写。USDCNY 中间价最多做低权重慢变量或纯展示。
- **AI 直接生成策略**：降级为研究助理（见 §8）。
- **外部信号跟踪**：降级为纯观察列表，明文永久无背书资格、无入池权限
  （信号历史不可得或带幸存者偏差，按"有回测才算数"的前提进不了门）。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│ 账户风控层 (P0)   回撤熔断 + 板块集中度闸门               │ ← 策略无关，任何主策略无权穿透
├─────────────────────────────────────────────────────────┤
│ 策略调度层 (P4)   市况 → 查背书矩阵 → 建议/切换主策略      │ ← strategy_switches 审计表
├─────────────────────────────────────────────────────────┤
│ 策略插件层 (P1)   registry + Strategy 协议                │ ← mid/short 首批插件，判定函数零改动
├─────────────────────────────────────────────────────────┤
│ 市况识别层 (P2)   regime.py 引擎                          │ ← 判定+因子读数全落库、全版本化
├─────────────────────────────────────────────────────────┤
│ 数据层     (P2)   全市场日线库 + 既有四源降级链（不动）    │
└─────────────────────────────────────────────────────────┘
展示层：/strategy 策略中心页 + 首页灰条 + 日报备注
```

与既有开仓门的关系：**开仓门（11c，沪深300 MA60 滞回）是硬否决层，一行不动**——
门关 = 任何策略都不开新仓。市况引擎只决定"由哪张规则卡产生候选信号"（P2 阶段连这个都
不决定，纯展示）。两台状态机独立留痕，各自的 kv 键互不复用。

## 3. P0 · 账户风控层 + 库迁移（几天量级，先于一切）

即操盘手审计的实盘前三件事，外加趁 trades=0 做一次性迁移。
**三项完成且三测全绿之前，P1 不开工。**

### 3.1 回滚线重定

主判据改为**账户级回撤 -8% 熔断**；「前 20 笔胜率 <20% 回滚」降为辅助观察项
（审计实算：胜率线误杀正常系统概率 22~25%，对真退化仅 41% 检出）。
实盘 0 笔，改判据不违反三参数冻结。熔断触发 = 停止新开仓 + 推送 + 首页红条，
恢复须人工确认留痕。

### 3.2 板块集中度闸门

- pool 加 `industry` 字段（Tushare stock_basic 的 industry，入池时写入；存量回填）。
- 硬闸：买入卡生成与自动研究入池时，计算"同行业持仓+等买点金额占账户总额比例"，
  超 30% 拒绝并说人话（"AI算力链已占 xx%，这票先不进"）。拒绝落库（对齐 11e 拒绝落库惯例）。
- 当前池内 7/9 只挤在 AI 算力链，此闸上线即有真实约束力。

### 3.3 风险话术诚实化

- 验证期单笔风险 RISK_PCT 2→1（走 params.set_params 审计+版本号）。
- 买入卡话术改为"计划止损 X%（跳空可能击穿，历史最深 -19%）"——
  审计实锤：一半 E1 止损被跳空击穿，"最多亏2%"话术失真。

### 3.4 三表迁移（一次做掉）

- pool / positions / trades 各加 `strategy TEXT`；pool 加 `industry TEXT`。
- 用 storage.init_db 既有幂等模式（PRAGMA table_info + ALTER，storage.py 有现成范本）。
- 存量策略归属：逐行按当日 snapshots payload 的 mode 字段核定；关联不上或矛盾标
  `strategy='unknown'`（unknown 永不进背书矩阵样本），回填出对账报告留档。
- 迁移脚本照抄 migrate_exdiv.py 骨架四件套：**默认 dry-run / --apply 走 sqlite3 backup API
  （WAL 库禁 shutil 复制）/ 脚本自带 init_db / 幂等防重跑**。
- 时点：必须在首笔实盘之前完成（当前 trades=0、positions=0、pool 活跃 9 行，
  迁移成本历史最低点）。

## 4. P1 · 策略插件层（一周量级，收窄口径的重构）

### 4.1 范围（明确收窄）

注册表**只接管两处分叉**：eod.py 逐只 scan 分叉与持仓出场分叉。
开仓门滞回、池同步、日报、brief、自动研究**原地不动**，`if mode != "short"` 判断改为
读插件能力声明（`supports_pool` 等），语义等价、diff 最小。
下游通用化（daily/brief 的 mid 专属状态词、池状态机词汇）推迟到真有第二个长线策略
落地时按需做，届时按"先原型后编码"流程单独立项。

### 4.2 Strategy 协议（strategies/base.py）

```python
class Strategy(Protocol):
    id: str                    # "mid" / "short" / 未来新策略
    name: str                  # 白话名："中线卡 v0.2"
    horizon: str               # "short" | "mid" | "long"（短线/中线/长线；
                               #  快照 mode 字段映射：short→"short"，mid/long→"mid"，取值域不扩）
    scan_window_days: int      # scan 所需最小取数窗（自然日）
    exit_window_days: int      # check_exit 所需最小取数窗（mid=520, short=CONFIG 同款）
    supports_pool: bool        # 能力声明：池同步/日报/自动研究是否启用
    def scan(self, df, ctx) -> dict: ...
    def check_exit(self, df, position, ctx) -> dict: ...
```

ctx 键名**定死三个，禁用裸 `gate_ok`**：
`market_gate_open`（大盘开仓门，滞回后）/ `fundamental_gate_ok`（个股基本面闸门）/
`regime_label`（市况，P2 起提供）。mid 包装器内部把 `fundamental_gate_ok` 映射回
analyze_mid 的原参数名。验收含 grep 级检查：strategies/ 下不许出现不带前缀的 gate_ok。

### 4.3 五条防雷铁律（全部来自审查实锤）

1. **settings 现有键名一个不许改、不许迁移**。参数命名空间只在注册表内部做映射层
   （沿用 params.py MID_KEY_MAP 既有模式）。防冻结参数（ENTRY_A_MAX_GAIN=12 /
   ENTRY_A_STOP_BUFFER_PCT=5 / DD_EXIT_PCT=18）因键名搬家静默回滚到旧语义（0/0/25）。
   加固测试：settings 写 ENTRY_A_MAX_GAIN=12 → params.apply() → 断言
   CONFIG_MID["ENTRY_A_MAX_GAIN"]==12。
2. **持仓检查按持仓行 strategy 字段选该策略的 exit_window_days 取数，不吃主扫描缓存**
   （或 hist_cache 按 (code, 窗口档) 分桶）。防"short 当主策略的日子里查 mid 持仓"时
   520 日窗被 300 日窗顶替，E1 止损上移/E3 回撤止盈漏判早期高点。
   镜像测试：构造 entry_date 早于短窗起点的 mid 持仓，断言两种主策略编排下
   check_exit_mid 输出逐字节一致。
3. **适配器取数一律晚绑定**（调用时经 data 模块属性现取），禁止把 data/params 函数对象
   存进注册表——否则 test_web 的名字级 monkeypatch 静默失效，用例绿着走真实网络。
   验收加"mock 命中计数>0"断言。
4. **check_positions 包装三个默认值陷阱**：fetch/positions 设为 keyword-only 必传，
   构造时 assert 非 None（禁止吃引擎默认的 akshare 原版 get_hist 和 positions.csv 旧路径）。
   eod._check_positions_mid 里复刻的 eff_stop 口径与 check_exit_mid 收进同一 mid 插件模块，
   加镜像测试钉死。brief.py sell_line 直读 CONFIG_MID 的耦合同步收口：改由持仓检查结果
   的结构化字段传递。
5. **MODE 键退役为只读兼容**（params.get_mode 保留为兼容包装），新概念 ACTIVE_STRATEGY
   在 P1 阶段恒="mid"，切换入口到 P4 才有。

### 4.4 快照契约兼容

- payload 新增 `strategy` 字段；`mode` 字段保留且**取值域不扩**（永远 short/mid，
  映射自策略 horizon），旧消费端零改动。
- 兼容空键垫（"focus":[], "breakout":[] 等）由注册表统一注入，不靠插件自己记得。
- eod._prev_snapshot_states 改为 `prev.get("strategy", prev.get("mode"))==当前策略`
  才比对，防不同策略快照状态词互比产出假 tech_shift 事件。

### 4.5 验收（golden master，不止三测）

- 重构前后同一套 fixture 跑 run_eod_scan，payload 逐键 diff（剔除 elapsed_sec/created_at）
  **必须为空**。三测全绿不构成"零变化"证据（test_web mock 掉大半真实路径）。
  diff 工具脚本入库可复跑。
- 上线首晚人工 diff 新旧两天快照的 payload.config_mid，逐键相等。
- 三测全绿 + 生产实例 launchctl kickstart + curl 验收（任务 13 运维规矩）。

### 4.6 顺手补的账

backtest.py 补双边费用 0.15%（与 backtest_mid.py FEE_PCT 同口径），重跑短线全量回测。
没有这个，P3 矩阵里短线成绩是费前虚值，与费后中线成绩不可比。

## 5. P2 · 市况识别引擎 + 数据层 + 策略中心页（两周量级，只展示不切换）

### 5.1 全市场日线库（新子系统）

- 新表 `market_daily`（trade_date, ts_code, close, pct_chg, high, low, amount…）+
  `adj_factors`（trade_date, ts_code, adj_factor）。
- 每日增量：EOD 收盘扫描时 `pro.daily(trade_date=当日)` 一次全量（约 5400 行，
  低于单次 6000 行上限，每天 1 次调用）+ `pro.adj_factor(trade_date=当日)`。
- **按 trade_date 维度拉取而非按股票循环**：天然含后来退市的票，point-in-time 免费正确
  （按股票循环会漏掉 5 年里退市的几百只，宽度序列 2021~2023 被系统性抬高）。
- 5 年回填：约 1200 交易日 × 2 接口 ≈ 2400 次调用。断点续传脚本（落库已完成日期、
  限流指数退避、可分多晚跑）。用户已拍板升 Tushare 5000 分，回填预计几十分钟内完成。
- 对账验收：抽 10 个交易日的涨跌家数与第三方口径比对，误差>2% 查复权与退市处理。
- 失败兜底：复用任务 8 哨兵模式（30 分钟补跑），当日拉不到绝不拿旧数据充当日。
- 宽度口径：**全市场、不剔 ST**（宽度本就该全市场；现有 universe 快照是市值过滤后的
  巨盘口径，分化市会误报健康——这是砍掉"从快照算宽度"路线的根因）。
  新高新低用 close×adj_factor 后复权价滚动窗口计算（未复权价除权日出假新低）。

### 5.2 市况分类器（regime.py，两维正交）

三分类（趋势/震荡/熊）维度混乱（下行趋势无处安放），改两维正交：

- **方向轴**：沪深300 close vs MA60 + MA60 斜率符号 → 多头 / 中性 / 空头
- **风险轴**：20 日已实现波动率滚动分位（滚动 500 日窗，禁全样本分位——防前视）+
  全市场宽度（涨跌家数、20 日新高新低占比）→ 健康 / 恶化
- 两轴合成 3×2=6 个组合，对外呈现时合并命名为 4~6 个白话市况
  （如"上行趋势市 / 高波震荡 / 阴跌熊市"；确切合并映射在 P2 原型阶段定稿），
  展示层用白话，库里存结构化二维标签。
- 滞回：**Schmitt 双阈值**（进入需分数>上阈值，退出需分数<下阈值，带宽内维持原判），
  计数滞回（连续 N 日）只做二道防线。

**反过拟合纪律（成败前提）**：

1. 因子、阈值、权重**只准用 2015~2021 段设计**，定稿打版本号冻结（regime_v1）；
   2022 至今是分类器的样本外验收段，设计期间不看 OOS 段走势。
2. 验收标准（写死，作为 P2→P3 闸门）：OOS 段年均翻转≤6 次、市况持续期中位≥20 交易日、
   不同市况下沪深300 未来 20 日收益分布显著差异（Kruskal-Wallis p<0.05）。
   **最后一条不过 = 标签对未来无信息量，项目停在仪表盘，不再往 P3/P4 走。**
3. 三个历史案例验收用例（期望标签事先写死）：2015-06 崩盘、2018 全年阴跌、
   2024-09 逼空反转。回填结果对不上 = 分类器不合格。
4. 任何标准化只准用滚动窗口统计量。
5. 因子准入三件套：**全期（回填+在线）同口径可得 + 在线增量路径 + 缺失时降级行为**，
   三件齐才准进评分。"历史有、在线没有"（或反之）的因子整个剔除。

### 5.3 regime_history 落库与版本化

每日一行存全：judged_date / regime 标签 / score / engine_ver / 全部因子原始读数 JSON
（含缺失标记）/ 数据源标识 / computed_at。**只追加禁回改**（SQLite UPDATE 触发器拦截），
保证任何历史日的判定可字节级重放。引擎参数纳入 params.set_params 审计+版本号体系；
引擎改版触发矩阵全量重算并标注 engine_ver，不同 engine_ver 的矩阵禁止混用。

### 5.4 策略中心页（/strategy）v1 + 全站接入

- 市况仪表盘：当前市况大字 + 各因子读数与白话解释 + 历史市况带状图（叠沪深300 K线下）+
  DeepSeek 白话解读（只解读不判定；调用范围=展示范围，每日缓存一次）。
- 首页开仓门灰条旁加一句市况白话："当前：阴跌熊市——开仓门关着是对的，零捕获正常"。
  这是治空窗期手痒的核心交付。
- 日报机械层加一行市况标注（不改机械层判定逻辑）。
- 板块资金流等展示性信息：拉得到显示，拉不到空着，永不进判定。
- 页面遵守"先原型后编码"：动代码前出 docs/原型-策略中心-*.html 给用户拍板。

## 6. P3 · 背书研究（9 月前后，离线报告 = 10-09 评审材料）

### 6.1 backtest_endorse.py：策略×市况矩阵

- 输入：各策略回测 trades CSV（已含 buy_date）× regime_history 历史标签（按入场日归段）。
- **训练段/OOS 段区分**（对齐 §5.2 反过拟合纪律）：准入资格只看分类器 OOS 段
  （2022 至今）的分段成绩；训练段（2015~2021）成绩仅作参考列，UI 灰显——
  防"分类器定义内含哪段行情赚钱"的同义反复污染矩阵。
- 主排序指标 = **费后日均收益率**（每笔 pnl ÷ 持仓天数加权均值；跨长短线唯一可比口径），
  "期望/笔"降为辅助展示列，绝不参与排序。
- **资格门槛（复合，缺一不可）**：
  1. 分段样本 ≥30 笔；
  2. 来自 ≥3 个**不相邻**的同市况区段（防"30 笔全来自 2025 一个区段≈1 个观测"）；
  3. 单一区段利润贡献 ≤50%；
  4. 剔除表现最佳单一年份后期望仍 >0（直接针对"2025 依赖"病灶）；
  5. 按市况区段 block bootstrap（整段重抽保留段内相关），费后期望 95% 置信下界 >0。
- 矩阵每格强制展示：置信区间 / 区段数 / 最大单段利润占比 / 按年份分解。
  达不到门槛显示"背书不足"而非裸点估计。**接受矩阵大部分格子长期是灰的——诚实不是缺陷。**
- 重算触发条件：新增实盘 ≥20 笔或 regime 引擎改版（不搞日历月度仪式）。重算走审计留痕。

### 6.2 backtest_switch.py：整机端到端回测（P4 的准入闸门）

- 用 point-in-time 市况标签 + **as-of 背书矩阵**（每个历史日只用截至当日数据重算矩阵，
  禁用终局矩阵——防矩阵层前视）完整模拟：
  判市况 → 查矩阵 → 任期约束 → 切换 → 新开仓走新策略 → 老仓走旧策略 →
  最小仓/减半仓稀释 → 管道空窗，输出组合级费后净值。
- **基准两个**：① 一直持有中线卡；② 固定"中线+防守二态"（即现有开仓门，两行代码对照组）。
- 准入标准：费后跑赢两基准且最大回撤不劣于基准。**跑不赢 = 全自动永久免谈；
  建议卡形态是否上线由 10-09 评审看数字决定，评审否掉则停在 P2 仪表盘。**
- 附每次切换事件的边际盈亏分解表 + "市况降级后存量持仓的后续回撤"单列指标。
- 切换层超参（任期/滞回/带宽/样本门槛）跑敏感性网格
  （任期{5,10,20,40}×滞回{2,3,5}日×带宽{0.5,1,2}%），**取绩效平台区中心而非最优点**；
  绩效排序随参数明显翻转 = 系统结构性脆弱，不予上线。全部超参纳入 set_params 审计。

## 7. P4 · 切换器（2026-10-09 评审拍板后上线）

### 7.1 审计与入口

- 新表 `strategy_switches`：ts / from_id / to_id / regime / endorsement_snapshot /
  trigger（auto | manual | 建议卡确认）/ engine_ver / matrix_ver。
- 唯一入口 `strategies.set_active()`：校验注册表存在 + 写表 + 推送 + 首页灰条，
  **明确不碰 RULE_VERSION**（rule_version 是 trades 统计分段键，切换若走 set_params
  会把实盘统计剁碎）。红线文档补一句："主策略切换必须走 set_active，与 set_params 平级审计"。
- 回滚线/熔断的计数口径按 strategy 字段隔离。

### 7.2 形态：建议卡起步 → 达标升全自动

- **起步 = 切换建议卡 + 一键"照建议办"**（复用任务 15 复核卡现成模式）：EOD 推送建议
  （附市况判定 + 背书数字 + 反事实），用户点确认生效，确认与拒绝都落库。
- **升级全自动的两个条件**：① backtest_switch 整机回测达标（§6.2）；
  ② 建议卡阶段人机一致率高（用户基本每次照办 = 自动化不改变决策只省手续）。
  用户的全自动终点不变，带着证据上岗。
- 防抖闸门（代码硬闸）：最短任期 20 交易日、年切换 ≤4 次。
- 反事实与熔断：每次切换记录"若不切换，旧策略同期成绩"；季度复盘切换累计 alpha，
  为负 → 自动退回单策略模式。

### 7.3 并行管道与互斥边界

**已背书策略的信号管道每日并行常开**（各策略 scan 都跑、池都同步——K 线已在内存，
多一遍 analyze 是纯本地计算，不烧 AI 钱）。互斥只发生在"谁有资格产生买入指令"这一层。
理由：mid 信号链 = 候选 10 日 → 研究 → 观察才出买点，管道停转后切回来面对空池，
数周开不出枪，且背书矩阵测的是"管道常开"的系统——不并行，矩阵期望直接失真。
（注：这与"不搞数月影子期"不冲突——不是延迟切换的观察期，而是让每台机器保持热机。）

### 7.4 验证期两层制

- **账户级执行验证**：实盘前 20 笔最小仓，验证人与链路（E1 实际亏损分布 / 信号捕获率 /
  E3 执行精度），全账户**一次性**，不随策略复制。走完出验证报告。
  **账户级验证期走完之前，P4 不上线、任何新策略不得成为主策略。**
- **策略级统计资格**：完全由背书矩阵承担（§6.1 五重门槛就是策略的"验证期"）。
- 新策略实盘热身：首 10 笔减半仓（不是独立 20 笔验证期，不重置账户级验证状态）。
- 若未来引入纸面预验证：策略获背书后 EOD 纸面记录信号，零成本累计，不占资金。

### 7.5 存量持仓处置（明文声明）

v1 **不动存量**：老仓按建仓策略管到平仓（红线安全，判定函数零改动）。
已知残余风险明文写入本节：市况降级为熊市时存量敞口不变。
backtest_switch 报告单列"降级后存量回撤"指标把代价摆上桌面，
10-09 评审看数字决定是否加组合级止损收紧（若加，作为叠加层不碰判定函数）。
混合期内对旧策略持仓的任何手动操作必须走复核裁决留痕（对齐 11e）。

## 8. P5 · 策略生产线（P4 之后，持续）

- **第一个新策略**：移植 1 个经典防守/震荡策略（低波动或双均线类，有文献有长历史），
  走完整流程：规则代码 + 等价于 test_rules_mid 的判定测试 + 全量费后回测 + 背书矩阵
  → 注册。候选策略年度配额 ≤2 个（防 winner's curse 批量制造候选击穿背书门槛）。
- **AI = 研究助理**：只产出策略假设文档；必须人工翻译成规则代码、补判定测试、
  过全量回测才能注册；注册事件记录批准人（用户签字，逼自己读懂判定语义）。
  AI 生成过程碰过的数据段一律不算背书，须在未参与迭代的 holdout 时段单独背书。
- **外部信号**：纯观察列表。明文：永久无背书资格、无入池权限。

## 9. 横切面

### 9.1 错误处理

- 因子数据缺失：带缺失标记降级判定（只用可得因子并在页面标注"今日缺 X 因子"），绝不静默。
- 日线库拉取失败：哨兵 30 分钟补跑（任务 8 模式）；当日数据未达前 regime 判定标"数据未齐"。
- **代码指纹**：启动时对 strategies/*.py + eod.py + rules_mid.py + screener.py + regime.py
  算 sha1 存 code_fingerprint，写进快照 payload 与 /api/health；/strategy 页对比磁盘现算值，
  不一致亮红条"代码已改未重启"。交付 restart.sh（kickstart + curl 断言 fingerprint 已刷新），
  写进 CLAUDE.md 必跑清单。防"审计流水记录已切换到策略X v2、进程里跑的是 v1"。

### 9.2 测试

- 三测底线不动：test_rules 只许加不许改；改动后三测必须全绿。
- 新增 test_regime：分类器单元用例 + 三个历史案例验收（§5.2，期望标签事先写死）+
  滚动窗口标准化断言（喂含未来数据的序列，断言判定不变）。
- P1 golden master diff 工具脚本入库可复跑；镜像测试（§4.3 之 2、4）进 test_web。
- 每期交付后照惯例跑多代理对抗审查，确认缺陷全修后上生产。

### 9.3 审计与纪律强化

- 冻结从纯纪律升级为代码强制：settings 加 freeze_until 键，params.set_params 在冻结期内
  对冻结键拒绝写入并落审计事件；解冻走带版本号的显式操作。
- regime 引擎参数、切换层超参全部纳入 set_params 审计+版本号+冻结期体系
  （防"管住士兵的枪，放跑指挥官"）。
