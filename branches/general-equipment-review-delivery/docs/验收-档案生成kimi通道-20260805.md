## 3. 配置与密钥边界

| 配置项 | 默认或来源 | 说明 |
| --- | --- | --- |
| `ARCHIVE_AI_ENGINE` | `kimi` | 只控制产业档案初稿通道；可由操作者显式改为 `claude_code` 或 `api` |
| `KIMI_API_KEY` | 进程环境或仓库外配置 | 无默认值；缺失即报错，不降级 |
| `KIMI_MODEL` / `kimi_model` | `kimi-k3` | 进程环境优先，仓库外配置次之 |
| `KIMI_BASE_URL` / `kimi_base_url` | `https://api.moonshot.cn/v1` | 进程环境优先，仓库外配置次之 |
| `KIMI_CONFIG_PATH` | `~/.config/guanlan/kimi.env` | 只允许指向仓库外文件；仓库内路径会被拒绝 |

密钥可只放进服务进程环境；需要落盘时，位置是 `~/.config/guanlan/kimi.env`，文件不属于仓库和镜像。实现和验收没有读取或记录密钥值，没有把响应正文或底层异常原文放进错误信息。HTTP、超时、响应结构、工具调用和规格校验失败均返回固定或截断后的安全错误。

## 4. 通道选择和 `$web_search` 循环

生成流程如下：

1. 服务端读取当前档案通道；默认得到 `kimi`。
2. 组装与既有通道相同的数据骨架和 `industry-archive-v2.1-web` Prompt。
3. Kimi 请求携带 `tools: [{type: builtin_function, function: {name: $web_search}}]`。
4. 若返回 `tool_calls`，保留完整 assistant 消息，并按官方格式回送 `$web_search` 的参数；最多 8 轮。
5. 只有已经发生联网工具调用且最终返回非空正文，才进入既有七节、深度和核心股不超过 5 只的校验。
6. 校验通过后写入初稿和生成元数据；失败则恢复 `skeleton_ready`，清空本次通道与模型元数据，并保留安全错误。

没有通用 fallback。Kimi 失败时接口只提示检查 Kimi 配置；只有操作者修改 `ARCHIVE_AI_ENGINE` 才会改走其他通道。
