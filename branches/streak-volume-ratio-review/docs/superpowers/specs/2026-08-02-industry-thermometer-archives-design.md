# 产业温度计与产业档案页设计

**日期：** 2026-08-02  
**状态：** 用户授权按需求自主完成，无须逐项讨论  
**范围：** 新前端追加纯展示功能；零交易，零策略、风控、选股和交易路径改动

## 1. 目标与非目标

本功能在“股票池”增加第三个子页签“产业档案”。页面顶部用行业药丸展示申万二级行业温度，下方列出仓库内的 Markdown 产业档案。个股详情仅在行业匹配时显示“产业档案”链接。

本功能不产生交易信号，不改变股票池，不进入影子运行，不连接收盘扫描、策略、风控或交易端点。它不写 `screener.db`、`market.db` 或 T1 研究库。

## 2. 数据事实与截止日

现场核对得到下列事实：

- 主目录 `S3_research.db` 只有空表。
- 完整 T1 库位于保留的 `codex/s3-stage1-data-clusters` 工作树，含 2,674 个交易日、358,316 条集群日状态、7,485,497 条集群成员日记录和 10,796,305 条成交量记录，截止 2025-12-31。
- 主目录 `market.db` 截止 2026-07-31。完整 T1 库的 `warm_daily`/`warm_adj_factor` 只覆盖 2013-12-02 至 2014-12-31，不能承载 2025 年成交额和 RS；因此成交额与复权收盘只读复用既有 `market.db`。两库截止日不同，界面不得把 2025-12-31 的温度写成“今日”。

温度计使用环境变量 `T1_RESEARCH_DB_PATH`，行情库使用 `MARKET_DB_PATH`；未配置时分别回退到现有 `S3_RESEARCH_DB`/本地 `S3_research.db` 与本地 `market.db`。等效环境只通过 LaunchAgent 克隆副本注入路径；生产 plist 不改。界面始终显示实际 `data_date`。

## 3. 方案比较

### 方案 A：请求时只读计算，内存缓存（采用）

首次请求从 T1 库与既有行情库计算最新共同交易日温度，两份数据库文件尺寸与修改时间均未变时复用内存结果。该方案不增加数据表、定时任务或写路径，任一数据库换日后自动失效。代价是文件变化后的首个请求需要数秒计算。

### 方案 B：定时生成 JSON 静态文件

此方案读取快，但必须新增收盘钩子和写文件路径。它扩大了生产运维与失败面，违背“数据只读”边界。

### 方案 C：在浏览器加载原始数据并计算

此方案可避免后端新模块，但会向前端暴露大量原始记录，下载量大，且难以对 SQLite 只读语义和口径做自动化验证。

## 4. 四灯冻结口径

计算日 `D` 为 T1 库 `cluster_daily`、`daily_vol` 与既有行情库 `market_daily`、`adj_factors` 共有的最新交易日。历史成员按 T1 时点口径判定：`in_date <= d` 且 `out_date` 为空或 `out_date >= d`。

1. **集群灯**：`cluster_daily.hit_count_10d >= 3`。该字段是 T1 冻结的“10 日内不同成员创 250 日新高数”，不在展示层重算替代口径。
2. **量比灯**：先计算行业量比 `D 日时点成员成交量合计 / 前 20 个交易日各日时点成员成交量合计的均值`。在有效行业横截面中按量比降序排名；第 6 名至前 `ceil(N/3)` 名亮灯。前 5 名不亮量比灯，直接触发“烫”。分母不含 `D`，避免当日成交量稀释自身量比。
3. **成交占比灯**：对截至 `D` 的最后 5 个交易日，逐日计算 `行业时点成员 market_daily.amount 合计 / 全市场当日 amount 合计`。5 个值严格递增时亮灯。
4. **龙头强度灯**：用既有 `market_daily.close * adj_factors.adj_factor` 计算个股 120 个有效交易日收益率。行业内 RS 最高者为链上龙头；龙头的全市场 RS 分位大于等于 85% 时亮灯。不足 121 个有效收盘的股票不进入 RS 横截面。T1 `stock_basic` 无名称列时显示股票代码，不猜测名称。

合成规则与用户定义一致：0 灯=冷，1—2 灯=温，3 灯=热，4 灯或量比进入前 5=烫。任一必要指标缺失时，该行业显示“缺数”，不将缺数当作灭灯。

## 5. 只读保证与缓存

新模块只能通过 SQLite URI `file:<absolute-path>?mode=ro` 连接 T1 库和既有行情库，并对两者执行 `PRAGMA query_only=ON`。模块不导入 `storage`、`eod`、`params` 或交易模块。新 API 只接受 GET。

缓存键包含 T1 与行情文件各自的绝对路径、字节数和纳秒修改时间。任一值改变时重算。缓存只存在进程内存，不落盘。

## 6. 产业档案协议

档案根目录固定为 `docs/产业档案/*.md`。每次 GET 请求扫描目录，因此提交新 Markdown 文件后无需登记表或后台管理页。

支持以下 YAML 头：

```yaml
---
industry: [通信设备, 半导体]
updated: 2026-08-02
status: 持续跟踪
---
```

`industry` 可为单个标量、逗号分隔标量、YAML 内联列表或多行列表。`updated` 必须为 `YYYY-MM-DD`，`status` 必须非空。缺失或非法头部的文件不进入列表；API 返回可诊断的错误项，不中断其他档案。

档案 ID 取 NFC 归一后的文件名 stem，只能通过已扫描目录反查路径，禁止用请求参数拼接文件路径。Markdown 通过 `markdown-it-py` 的 CommonMark 模式渲染，启用表格，禁用原始 HTML。

首批包含：

- `产业档案-存储与算力硬件链.md`；
- 把 `docs/研究-五年涨幅王画像与系统对照-20260718.md` 复制到档案目录，保留正文并补充 YAML 头。

## 7. API 设计

### `GET /api/industry-thermometer`

返回：`ok`、`data_date`、`formula_version`、`source`、`industries`、`coverage`。每个行业包含行业代码与名称、四灯布尔值、灯数、温度、量比排名、成交占比序列、龙头与 RS 分位。

### `GET /api/industry-archives`

可选查询参数 `code`。返回档案元数据、解析错误和该股票在 `data_date` 的申万二级行业及匹配档案 ID。

### `GET /api/industry-archives/{archive_id}`

只从目录扫描结果反查文件，返回元数据和已过滤的 HTML。未知 ID 返回 404。

## 8. 界面与导航

股票池顶部增加“产业档案”子页签。该页顶部显示数据截止日和可横向滚动的行业药丸。药丸按烫、热、温、冷、缺数排序，并显示温度与亮灯数。点击药丸后，档案列表只保留 `industry` 包含该行业的文档。

桌面端使用左列表、右阅读区的两列布局。手机端把列表收为阅读区上方的紧凑横向卡片带，避免双列挤压。样式只使用新前端既有 Claude 风令牌。

深链格式为 `#pool/archive/<encoded-id>`。个股详情匹配到档案时，在关键数字卡显示“产业档案”行；点击后打开对应档案。无匹配时整行隐藏。

## 9. 失败与空状态

- T1 库不存在或无可用日期：温度区显示“T1 数据未就绪”，档案阅读仍可用。
- 行业无档案：保留已选行业药丸，列表显示“该行业尚无档案”。
- 单个 Markdown 头部非法：跳过该文档，其他档案继续显示。
- 文档在列表加载后被删除：详情返回 404，前端显示“档案已移除，请刷新列表”。

## 10. 测试与验收

TDD 顺序如下：

1. 先用最小 SQLite fixture 写温度计失败测试，覆盖四灯、前 5 直接烫、缺数、历史成员时点和只读连接。
2. 写档案失败测试，覆盖 YAML 标量/列表、自动发现、Markdown 表格、原始 HTML 禁用、路径穿越和个股行业匹配。
3. 写 API 与新前端合约失败测试，锁定第三子页签、深链、个股链接、手机布局和零写端点。
4. 实现最小代码后运行新测试和项目规定的四组回归测试。
5. 在生产等效环境中验收。LaunchAgent 克隆副本、工作目录、`start.sh`、FastAPI `FileResponse` 与生产一致；端口独立；生产库副本只读；T1 完整库与行情副本只读。记录生产 plist 字节哈希、生产库与副本启停前后哈希。
6. 截图覆盖桌面和手机的产业档案页及个股详情链接，并检查浏览器控制台、API 响应和写路径。
