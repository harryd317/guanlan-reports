# 交付总结 11c:开仓门硬闸门 + 滞回缓冲(2026-07-09)

> 自包含总结,可直接转发。体检批次第 6 件(小件收官,下一件是压轴的中线回测);
> 原型经拍板(A 灰化+违规记账小口子 / B 带宽±1%可调 / C 翻转推送)。

## 修的是什么问题(体检 high 级)

规则卡第 4 条写着"大盘关门(沪深300 跌破 60 日线)期间只卖不买",但生产链路里
它只是一条红色横幅——**门关着,系统照样发"明日开盘可执行"的买入卡**,同屏自相矛盾;
而且门是单日判定,指数贴线时天天翻转(实测 2026-07-06 靠 +0.04% 开门、次日一根
阴线就关),"关门"的纪律含义被噪声淹没。

## 做了什么

1. **门加 ±1% 滞回缓冲**(带宽 GATE_BAND_PCT,设置页可调):
   开着的门,收盘跌破 均线×(1-1%) 才关;关着的门,收盘站上 均线×(1+1%) 才开。
   反弹不足 1% 不轻易重开,消灭"开一天又关"的假信号;门状态持久化存档,
   每次翻转记日志并推送一条微信(渠道配好后生效);单日原始判定另存 ok_raw 供追溯;
2. **门关时买入卡降级**:整卡灰化 + 「大盘关门 · 不执行」灰标 + 观望说明
   ("卡只是记录,门开后若买点仍有效自动恢复可执行"),按钮只剩「知道了」;
3. **违规记账小口子**(拍板保留):红字链接"我没忍住已经买了→违规记账"——
   走与正常买入完全相同的成交价+金额确认流(仓位闸门照样校验),
   但留 `gate_violate_buy` 审计记录。账本诚实优先,破例有痕;
4. **后端同样硬**:门关时直接调接口买入也会被拒(防绕过前端),
   必须显式带违规标记才放行。

## 验证

- TDD 六用例先红后绿:滞回序列(开→带内维持→-1.05%关→+0.29%仍关→+1.22%开,
  两次翻转两条推送)、参数注册、门关降级/门开恢复、后端硬闸+审计痕、前端渲染、
  扫描主流程接线;
- 三测全绿:test_rules 8/8、test_rules_mid 16/16、test_web **360/360**(+6);
- 线上冒烟:重启后 market_gate 正确(7月8日收盘 4755 < 均线 4846,关门);
  今天恰好没有买入卡在场,降级态已由测试钉死,下次门关遇买点即生效。

## 影响面

- 规则引擎判定语义零改动(红线):滞回只改"门状态怎么算",降级只改呈现与确认流;
- 门的真实价值与带宽取值,将在 11g 中线回测中用历史数据复核,不合适再调;
- 违规/破例记录(gate_violate_buy、force_buy)同入 user_actions 表,
  将来可统计"破例次数与破例后的盈亏"——纪律的自我审计闭环。
