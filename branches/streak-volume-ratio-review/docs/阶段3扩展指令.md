## 一、交易台网页化(替代claude.ai里的纪律交易台工具)

1. SQLite新增表:positions(持仓)、trades(交易日志)、equity(净值历史)、rule_changes(规则审计)、memory_log(备忘录变更记录)
2. 新页面「交易台」:
   - 持仓录入:代码/名称/买入日/买入价/止损价/金额;录入界面实时显示"本笔若止损,账户亏X.XX%"风险标尺和仓位占比,超建议上限黄字提示但不阻止
   - 平仓归档:卖出日/卖出价/原因(止损破平台|破MA20|破前低|主动止盈|其他)/一句话复盘,归档后自动更新净值
   - 统计区:胜率/盈亏比/期望值/累计盈亏 + 验证期20格进度条(红盈绿亏);20笔期望为正显示解锁50/80,期望为负显示"改策略,不改仓位"
   - 回撤检查:净值距高点回撤≥15%,全站顶部黄条"新仓减半直至净值新高"
3. 一次性迁移入口:粘贴旧纪律交易台导出的JSON完成导入
4. 盘中监控区与持仓联动:持仓股票加入轮询,实时显示距止损价%

## 二、规则治理(AI提案制)

1. reviewer能力扩展:可输出结构化规则变更提案JSON{参数名,旧值,新值,理由};前端渲染为确认卡片,用户点「确认生效」才写入settings,点「驳回」则记录驳回
2. 每次生效变更写入rule_changes审计表:时间/参数/旧值/新值/理由/来源(用户手改|AI提案)
3. 规则版本号机制:任何参数变更version+1;每笔交易在录入时记下当时version;统计区支持"仅当前版本"和"全部"两种口径切换
4. 治理红线写入reviewer系统提示词:验证期未满20笔或期望为负时,若用户要求上调仓位上限,提案中必须注明"违反验证期原则"并拒绝主动发起此类提案;仓位参数的提案只能由用户发起
5. 边界:参数类改动走本机制;逻辑类改动(新否决条件、判定公式修改)明确告知用户"需回Claude Code修改并重跑测试",reviewer不得尝试改代码

## 三、本地记忆(双脑共享)

1. 项目根新建MEMORY.md,固定结构:当前规则版本摘要/验证期进度/近期关键决策(带日期)/待观察问题/复盘要点
2. reviewer每次对话自动注入:MEMORY.md全文+当日筛选快照+交易统计+最近3次对话的摘要
3. 对话中出现值得留存的结论时,reviewer主动生成"记入备忘录"提案(一段带日期的增量文本),用户确认后追加写入,同时记memory_log
4. CLAUDE.md开头加一行:"开工前必读MEMORY.md,这是本项目的共享事实文件"
5. 工作台加「导出复盘包」按钮:一键生成review_pack.md,包含净值序列/全部交易明细/规则变更史/MEMORY.md全文/当前参数,供用户带去claude.ai做深度复盘

## 四、验收标准

1. 录一笔模拟持仓→平仓→统计自动更新、验证期格子+1、净值变动正确
2. 对reviewer说"把追高线改到20%"→出现提案卡片→确认后settings生效、审计表有记录、版本号+1;再说"单票上限提到60%"→它注明违反验证期原则且不出提案卡
3. 新开一天的对话,问"我们之前定过什么关键决策"→能准确复述MEMORY.md内容
4. 导出复盘包,人工检查五部分内容完整
5. test_rules.py + test_web.py全绿;模拟数据清理干净后交付
