## 一、背景与拍板结论

用户反馈 /ask 页"不协调、用起来怪",确认的三个痛点:
1. **入口重复**:顶部体检框(11j)与底部"池外的票也能查"快捷键,都是"输代码查任意票";
2. **顺序别扭**:快捷键(行业/概念)沉在页面最底;体检框抢在标题下第一屏;
3. **视觉不统一**:体检卡、课文卡、聊天卡各写各的样式细节。

用户拍板:
- **结构选方案B(分区子页)**:页头三个分区按钮,每屏只做一件事;
- **查任意票 = 一条龙全出**:体检卡(规则判断+五年回放)+ K线 + AI白话解读,一次出齐;
- **池内跳转**:在「查任意票」输入池子里的票的代码 → 自动切回「我的课堂」并选中该票,不出重复内容;
- 分区名暂定:**我的课堂 / 查任意票 / 随便问**(用户未提异议,上线后可随时改文案)。

## 二、页面结构(方案B)

```
顶栏(不变):今日 | 问AI(高亮) | ⚙️
标题:问AI
副标题:学池子里的票、查任意一只票,或者随便聊。
分区按钮(segmented,3枚):📚 我的课堂 | 🔍 查任意票 | 💬 随便问
─────────────────────────────
屏1 我的课堂(默认屏)
  · 股票池横条(现有 poolbar,排序/副标题逻辑不变)
  · 课文卡(现有 lesson:①行业 ②技术面+K线 ③基本面)
  · 追问聊天(现有 chat,按票 reset)
屏2 查任意票
  · 搜索框(合并原体检框+池外查询,6位代码校验)
  · 一条龙:体检卡(/api/stock_test)→ K线(通用,无专属标注)→ AI白话解读(自动发)→ 追问输入
屏3 随便问
  · 两枚快捷 chip:🏭 分析一个行业 / 🎓 教我一个概念
  · 通用聊天(/api/review/chat),会话不随切屏清空
```

## 三、交互细节

### 3.1 分区切换
- 纯前端 show/hide,三屏 DOM 常驻,切换不丢状态(课文、体检结果、聊天记录都保留);
- 默认落「我的课堂」;
- URL `?code=XXX`(今日页跳转入口,兼容保留):池内票 → 课堂选中该票;池外6位代码 → 自动切「查任意票」并直接执行查询。

### 3.2 查任意票一条龙(时序)
1. 校验 6 位代码,非法 toast 提示(沿用现逻辑);
2. **池内票 → 切「我的课堂」+ selectStock,流程结束**(拍板);
3. 池外票:体检卡与 K 线并行拉取先出(秒级);AI 解读走 `/api/review/chat`(带【池外查询 code】前缀)自动发出,气泡先显示"AI 思考中…";
4. 追问输入框固定在一条龙末尾,继续走池外前缀通道;
5. 换代码重查:沿用 LESSON_SEQ 代次守卫模式,过期响应丢弃(现有机制,不新写)。

### 3.3 随便问(交互简化,变更点)
- 原 quickinput 独立弹出输入条**删除**;
- 点 chip → 聊天输入框聚焦 + placeholder 换成对应提示("输入行业名,比如:创新药"/"输入概念名,比如:止损"),发送时自动拼接现有前缀(【行业分析】/【概念教学】,QUICK_PREFIX 不变);
- 发送成功后恢复默认 placeholder("行业、概念、随便聊…");点另一枚 chip 则直接切换提示。

### 3.4 删除项
- 顶部独立体检框(checkupbar);
- 快捷键"池外的票也能查"(合并进屏2);
- 体检卡内"就这只票问AI"按钮(屏2追问框就在体检卡下方,按钮多余);
- quickinput 组件(见 3.3)。
