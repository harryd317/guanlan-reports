# T2 阻断报告：实际信号日资格陈旧

日期：2026-07-29

分支：`codex/s3-stage2-backtest`

结论：当前 T2 回测结果无效；不得进入 G1，不得启动 T5。

## 事实

`s3_backtest/data.py` 先在捕获候选上按当日检查申万二级、ST 与公告时点财务，再把最后一次合格
捕获保存在 `current`。后续等待买点期间，实际信号直接复用 `current` 的行业与资格，没有按实际
信号日重新检查。

这不是报告措辞问题，而是已经进入唯一一次样本外的结果级污染。

### 财务反例

- 股票：`601111.SH`
- 实际信号日：2022-03-25
- 原始交易：`reports/s3_backtest_trades.csv` 第 105 行
- 截至信号日最新已公开年报：公告日 2021-03-31，报告期 2020-12-31
- 净利润：-15,822,217,000 元
- 营收：69,503,749,000 元
- 上一份已公开年报营收：136,180,690,000 元

该公司同时满足“亏损”和“营收下降”，按冻结质地底线应在信号日被剔除，但原始样本外仍成交，
净收益 -7.2431%。

### 申万二级反例

| 股票 | 信号日 | 原始记录 | 时点正确行业 |
|---|---|---|---|
| `002516.SZ` | 2022-01-24 | `801131.SI` | `801093.SI` |
| `002595.SZ` | 2022-01-13 | `801072.SI` | `801074.SI` |
| `601111.SH` | 2022-03-25 | `801179.SI` | `801991.SI` |

因此行业 30% 上限也可能按错误行业计算。已抽查原始交易中没有信号日 ST，但代码同样没有在
实际信号日重检 ST。

## 为什么没有直接修复并重跑

用户已经冻结：

- 样本内参数选择规则不得修改；
- 结果出来后不得追加参数组合或重跑调参；
- 样本外只允许一次；
- 指令与代码现实冲突时必须停下报告，等待裁决，不得自行变通。

修复此问题后，有效信号集、81 组样本内结果、冻结最优参数和唯一一次样本外都可能变化。继续运行
必须明确采用新的预声明，或者由用户明确裁决如何处置已经作废的首次运行。

## 同次审查的次要问题

1. `sealed` 目前只是账本状态位，没有 SQLite 写保护触发器；存量结果读取时也没有复验结果哈希。
2. 年度表把“停新仓状态沿用”写成“该年触发”，导致 2016—2021、2023—2025 的表述不准确。
3. CSV 使用标准库默认 CRLF；完整 `git diff --check` 会把 CR 计作行尾空白。代码与 Markdown 检查通过，
   但不能声称不带排除条件的完整命令通过。

这些问题不改变首要结论：实际信号日资格缺陷已经足以使当前 T2 结果作废。
