# T7 生产等效环境修复设计

日期：2026-07-31
状态：方案 A 与六步设计已经用户批准；本文固化实施边界。
范围：复现并修复 T7 今天页空白和手机端挤压，完成生产等效环境验收与镜像复核材料。
部署状态：本轮不部署生产；验收通过后只申请重新部署。

## 目标

1. 用生产 LaunchAgent 配置的克隆副本，在独立端口启动 T7 分支。
2. 保持生产工作目录、启动脚本和静态文件服务方式的语义等效。
3. 用生产数据库的一致性副本提供真实数据；副本只读打开，全程不连接生产库。
4. 在修复前稳定复现今天页空白与手机端挤压，定位模板、静态资源、路径或缓存差异中的真实根因。
5. 根因确认后先提交稳定失败测试，再做最小修复。
6. 在等效环境完成今天、股票池、我的、工程模式、设置五页的桌面和手机验收。
7. 把十张验收截图同步到公开报告镜像。用户在镜像复核后，才可批准重新部署。
8. 把部署失败、回滚、根因、修复和验收证据写入事件记录与最终报告。

## 不在范围内

- 不修改生产 LaunchAgent 原配置文件。
- 不停止、重启、替换或部署生产实例。
- 不把生产数据库直接传给等效实例。
- 不改变策略规则、市场数据、交易语义或数据库结构。
- 不用隔离预览环境截图充当部署前验收证据。
- 不因等效环境验收通过而自动获得生产部署授权。

## 方案选择

### 方案 A：克隆 LaunchAgent，使用 T7 工作树

复制生产 plist，保留其启动方式，只改等效实例必须隔离的值：标签、工作目录、端口、环境变量和日志路径。等效实例仍通过同一 `start.sh` 启动同一 Uvicorn/FastAPI 应用，并由同一 `FileResponse` 路径提供静态页面。

采用此方案。它能复现生产启动链，同时把进程、端口、日志和数据与生产隔离。

### 方案 B：终端直接运行 Uvicorn

该方案无法覆盖 LaunchAgent 的工作目录、环境继承和启动脚本差异，不能解释本次“隔离预览正常、生产异常”的偏差。

### 方案 C：复制项目到临时目录后直接启动

该方案会引入另一套目录结构和文件状态，降低路径问题的可复现性。

## 一、生产等效拓扑

### LaunchAgent 克隆

生产 plist 只读来源：

```text
~/Library/LaunchAgents/com.rui.stock-screener.web.plist
```

等效 plist 使用克隆副本。副本至少改变以下字段：

```text
Label=com.rui.stock-screener.web.t7-equivalent
WorkingDirectory=<T7 工作树绝对路径>
ProgramArguments=/bin/bash <T7 工作树绝对路径>/start.sh
SCREENER_PORT=18787
SCREENER_NO_BROWSER=1
SCREENER_EQUIVALENT_MODE=1
SCREENER_DB_PATH=<运行证据目录>/screener.db
SCREENER_MARKET_DB_PATH=<运行证据目录>/market.db
SCREENER_S3_DB_PATH=<运行证据目录>/S3_research.db
stdout/stderr=<运行证据目录>
```

克隆文件放入独立运行证据目录，再用 `launchctl bootstrap` 启动。生产 plist 不写入、不格式化、不重新序列化。

### 启动脚本兼容

`start.sh` 中所有端口使用同一变量：

```bash
SCREENER_PORT="${SCREENER_PORT:-8787}"
```

端口探测、健康检查 URL、浏览器 URL 和 Uvicorn `--port` 都读取该值。不传 `SCREENER_PORT` 时仍绑定 `127.0.0.1:8787`，生产行为保持不变。生产 plist 无须增加环境变量。

### 应用与静态资源

等效实例必须通过 `start.sh` 进入生产使用的应用入口，不新增预览服务器或构建链。HTML、`nav.js` 和品牌脚本继续由 FastAPI 路由与 `FileResponse` 从 `WorkingDirectory` 下的 `static/` 提供。

验收证据记录：

- 等效 LaunchAgent 标签、PID、状态和端口；
- 等效进程的工作目录和完整参数；
- 首页、`nav.js`、品牌脚本的状态码、MIME、`ETag`、`Last-Modified` 与 `Cache-Control`；
- 生产实例 PID 和健康状态在等效模式启动前后均不变。

## 二、数据库只读隔离

### 一致性副本

启动等效实例前，为以下生产数据库生成 SQLite 一致性副本：

- `screener.db`
- `market.db`
- `S3_research.db`

副本通过 SQLite backup/checkpoint 语义生成，不能只复制可能仍有 WAL 未合并的主文件。副本放在被 Git 忽略的运行证据目录，并移除写权限。

### 只读打开

等效模式把数据库路径显式传给各存储模块。连接必须使用 SQLite URI：

```text
file:<absolute-path>?mode=ro
```

并设置 `uri=True`。等效实例不得回落到生产路径或工作树内的默认数据库。

等效模式还必须：

- 跳过数据库初始化、迁移和参数写入；
- 不启动收盘扫描、哨兵、推送或其他定时任务；
- 拒绝会写数据库的 HTTP 操作；
- 保留页面读取所需的只读接口。

如果任一模块不能只读启动，等效实例启动失败，不能降级为可写副本。

### 哈希证据

等效模式启动前和验收结束后，分别记录：

1. 三个生产数据库的 SHA-256；
2. 三个数据库副本的 SHA-256；
3. 生产 plist 原文件的 SHA-256。

前后哈希必须逐项一致。生产数据库哈希证明等效过程未改生产数据；副本哈希证明应用未写入副本；plist 哈希证明生产配置一字未改。

## 三、根因定位

### 修复前复现

先在 T7 当前提交上启动等效实例，不改页面代码。桌面使用 `1440 × 900`，手机使用 `390 × 844`。至少稳定复现：

- 今天页主体空白；
- 我的、工程模式或设置页出现生产曾见的手机端窄列、单字竖排或横向挤压。

如果异常不能复现，停止修复，继续核对 LaunchAgent、工作目录、静态路径、缓存和数据副本，不能凭猜测改 CSS。

### 证据采集

每个异常页面记录：

- 页面 URL、视口和截图；
- 浏览器控制台错误与失败请求；
- HTML 和静态资源响应头；
- `location`、活动路由、匹配的 media query；
- 根容器、主栏、页面容器和关键卡片的 `display`、`width`、`height`、`overflow`、`position` 与边界矩形；
- `documentElement` 和 `body` 的 `scrollWidth/clientWidth`；
- 正常缓存、禁用缓存、硬刷新三种结果。

隔离预览环境只用于对照差异，不进入部署验收证据。

### 单一假设与最小实验

根据证据形成一个可证伪的根因假设。每次只改变一个条件，例如工作目录、资源缓存、路由状态或一条布局规则，并重新采集同一组数据。实验必须把根因缩小到具体加载路径、模板状态或 CSS/JS 行为。

事件记录必须写明：

- 观察到的现象；
- 排除的候选原因；
- 确认根因的实验；
- 根因影响今天页和手机布局的机制；
- 为什么隔离预览未暴露该问题。

## 四、测试驱动修复

### 稳定失败测试

根因确认后，先写能稳定复现该根因的自动化测试。测试应断言用户可见结果，不只匹配实现字符串。最低覆盖：

- 今天页在等效启动条件下有非零可见内容；
- 手机视口的主要容器保持有效宽度，不产生单字竖排或非设计横向溢出；
- 根因涉及的资源或路由从 T7 工作目录正确加载；
- `start.sh` 不传端口时仍使用 8787，传入时使用 18787；
- 等效模式只读打开指定副本，禁用定时写入并拒绝写操作。

先运行测试并保存失败输出，证明测试在修复前为红。若测试意外通过，必须改进测试，不能先改实现。

### 最小修复

只修改修复根因所需的启动、路径、模板、脚本或样式代码。不得借机重构页面、改策略逻辑或扩大界面范围。

修复后先运行新增测试至绿，再运行项目规定的全量测试：

```bash
.venv/bin/python test_rules.py
.venv/bin/python test_rules_mid.py
.venv/bin/python test_web.py
.venv/bin/python test_regime.py
```

测试输出、用例数和提交哈希写入事件记录与最终报告。

## 五、生产等效环境验收

### 页面与视口

等效实例端口固定为 `18787`。验收五页：

| 页面 | 入口 |
| --- | --- |
| 今天 | `/#today` |
| 股票池 | `/#pool` |
| 我的 | `/#me` |
| 工程模式 | `/#me`，展开“工程模式” |
| 设置 | `/settings` |

每页各验收：

- 桌面：`1440 × 900`
- 手机：`390 × 844`

共生成十张截图。截图文件名包含页面、视口、T7 源提交和日期。

### 通过条件

每张截图必须来自等效 LaunchAgent 实例，而非其他预览服务。页面通过条件：

- 出现 T7 新界面的预期标题、卡片或表格；
- 今天页关键内容边界矩形宽高均大于零；
- 手机主内容区没有单字竖排、窄列挤压或非设计横向滚动；
- 桌面导航和主内容不互相遮挡；
- 工程模式默认关闭，验收截图按要求展开；
- 页面等待真实内容或明确空态完成后再截图；
- 浏览器无 page error、console error；
- 页面所需接口和静态资源没有失败请求；
- `scrollWidth` 不超过设计允许的 `clientWidth`。

任一页失败即停止验收，保留失败证据，卸载等效实例，回到根因定位或修复阶段。不得选择性提交通过页面。

### 用户镜像复核门禁

五页桌面与手机全部通过后：

1. 把十张截图放入 `reports/` 的 T7 验收目录；
2. 完成事件记录和最终验收报告；
3. 提交源分支；
4. 同步对应 `docs/` 与 `reports/` 到公开报告镜像；
5. 从镜像远端重新克隆或读取，核对十张文件与镜像提交；
6. 回报镜像提交哈希和可复核路径。

用户在镜像中复核十张截图并明确批准后，才可重新部署。镜像复核前，T7 状态只能写“修复已验收，等待部署批准”，不能写“已部署”。

- 用克隆标签卸载等效 LaunchAgent；
- 确认 18787 不再监听；
