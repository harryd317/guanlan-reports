## 二、产品一句话

一个跑在用户 Mac 本地的**一人版投研所**:每日收盘自动筛选中线信号 → 候选票经立项研究进入**严选池**(上限30只)→ 对池内票做**事件级持续跟踪** → 每天产出一份**必须给出具体下一步动作**的日报。核心哲学:**这套系统的 alpha 不在选股,在防人;每个功能都必须让用户的决策次数变少,而不是变多。**

## 四、两张规则卡

### 卡 v0.1|短线(保留为可选模式,一字未变)

1. 股票池:总市值≥500亿,剔ST/退市。2. 突破:收盘创60日新高且量≥1.5×20日均量→观察池跟20日。3. 入场:回踩+缩量+阳线止跌+未破平台(容差0.5%)。4. 否决:破位/距平台>15%/回调放量≥1.3×/沪深300收于日MA60下(只关开仓门)。5. 持仓出场:破平台/-8%/破MA20。6. **铁律:focus只由收盘数据判定。**

### 卡 v0.2|中线(新主模式,默认启用,3个月+持仓周期)

**捕获(进候选)——全部满足:**
- 总市值 ≥ 500亿,剔ST
- 收盘创 **250日新高**
- 突破日量 ≥ 1.5×20日均量
- **相对强度**:近120日涨幅在"≥500亿全体"中排前15%(percentile≥85,本地算)
- **基本面闸门(三选一)**:①最新业绩预告/快报净利同比≥+50%或扭亏 ②所属行业指数收于其周MA30上方 ③近30日有白名单重大事件(重大合同/BD授权/并购/回购增持,取自公告流)

**入场A|浅回踩**:突破后回踩、当日缩量(<20日均量)、阳线且收盘≥前收、收盘未破突破平台(容差0.5%)。止损=平台价。

**入场B|深回调再突破**(用户点名要的"回调很多"buy点):自主升高点回撤20~35%;期间收盘未破周MA30、未破突破平台;回调段日均量<主升段日均量的50%;**再度放量(≥1.2×20日均量)创20日新高**→入场。止损=再突破前整理区最低收盘价。一句话:不接下落的刀,买回调后的再突破。

**否决**:距突破平台涨幅>25%未回踩(只看不追)/回调收盘破周MA30(退回候选)/**大盘周线门:沪深300收于周MA30下→开仓门关**(只影响新开仓提示)。

**持仓出场(任一触发,当晚日报下达指令):**
- E1 止损:收盘<止损位;浮盈≥1R后止损上移至成本价
- E2 趋势:收盘<周MA30(参数 EXIT_WEEK_MA,可改20)
- E3 回撤止盈:自持有期最高收盘回撤≥25%
- T1 加速减半:收盘距周MA20乖离>40%,且当日天量滞涨(量≥3×20日均量、涨幅<2%)或长上影(上影≥2×实体)→减半

**仓位纪律**:单笔风险预算2%(风险=入场-止损),单票≤30%,总仓≤60%,同一故事(同行业/同题材)≤2只。

**铁律沿用**:入场A/B与一切出场,只由收盘数据判定。

**实现要求**:v0.2 写成新模块 `rules_mid.py`,纯函数(输入日K DataFrame+辅助数据,输出状态),**照抄 v0.1 的模式配 `test_rules_mid.py`**(至少10个用例:捕获、A、B、各否决、E1-E3、T1)。禁止改 screener.py 的 analyze()。周线由日线本地重采样,不新增接口。

## 五、严选池状态机与论点档案

**状态流**:`候选`→(用户点立项)→`研究中`→(用户点入池/否决)→`观察池`→(入场信号+用户执行)→`持仓`→(出场)→`冷却期`(止损后20个交易日,信号只报不买)→`移出`。

规则:
- 候选由捕获信号自动创建,10个交易日无人立项自动过期;已在池/冷却中的重复信号只记事件不重复建。
- 研究中:自动触发 Claude 立项报告,72小时倒计时,超时日报催办。
- 观察池+持仓合计 **≤30只**;满员时新立项必须先回答"替换谁"(按 sort_score=七因子分×技术状态排序给建议)。
- **入池/入场/出场的执行确认永远是人**;系统只下达指令和记录。

**论点档案(入池时刻,系统最值钱的动作)**:Claude 按用户的七因子记分卡逐项找证据(带来源链接),并**强制输出空头报告——这票失败的三条路径 + 每条路径的可观测信号**。存 thesis 表。此后一切事件解读只回答一个问题:**"它验证了还是削弱了当初的入池论点?"** 卖出理由从此只有三种:技术出场触发 / 论点被证伪 / 被更好的票替换。

## 六、日报规格(本版本的核心交付)

**生成时点**:每交易日收盘筛选流水线末端自动生成(15:20任务串联:筛选→事件采集→池状态更新→日报→macOS通知"日报已生成:今日待办N件");提供手动重生成按钮。

### 机械层(每日必产,零API成本,决定性规则生成)

**头部|今日待办**:全池按优先级排序的指令清单,`EXIT/TRIM > ENTER/ENTRY_READY > REVIEW > WATCH临近`,每条一行、可点进个股。首屏必须直接回答"我今天要做什么";没有待办就大字"今日无操作"。

**逐票卡片(池内每只必有)**:状态徽章 / 收盘与涨跌 / **与关键位的距离**(止损位、周MA30、平台价、减半线,全部带具体价格和百分比)/ 今日事件diff(无则"无")/ **下一步(必填结构化字段)**:

```
next_action = {type, condition, price_level, deadline}
type ∈ HOLD | WATCH | ENTRY_READY | ENTER | TRIM | EXIT | REVIEW | REMOVE
```

示例文风(指令单,不是研报):
- 「HOLD|无事。止损26.40(-9.2%),周MA30 27.15(-6.6%),距减半线还差18%。」
- 「WATCH|等回踩41.0±0.5且当日量<20日均量;满足则次日看止跌阳线。」
- 「EXIT|收盘98.20<周MA30(101.3),明日开盘执行清仓,依据E2。」
- 「REVIEW|今日公告削弱论点第2条,48小时内复核,周五前给结论。」

**禁模糊词(验收硬标准)**:「持续关注」「保持观望」「注意风险」「逢低布局」等**不带数字条件与期限的建议一律违规**。每条建议必须含:具体价位或条件 + 触发后的动作 + 期限。

**尾部**:大盘周线门状态 / 池子概况(各状态数量、今日迁移)/ 风险检查(总仓位、单票集中度、同故事≤2只是否超限)/ 一句免责:建议=系统纪律的输出,终判在人。

### Claude层(仅事件触发,控制成本)

触发条件:新公告或业绩披露 / 技术状态迁移(入场信号、破周MA、减半触发)/ 行业指数周线变档 / 入池立项。输出:该事件**验证/削弱/无关**于论点档案哪一条 + 是否改写该票今日 next_action + 三句话内的解读。**无触发的票,Claude一个字不写**——"无事发生"这一行本身就是产品,它保护用户的持有力。

**周报**:每周六10:00(Asia/Shanghai),全池复盘 + 行业仪表盘解读(见七)+ 下周关注日历(财报披露日、解禁、已知事件)。

**成本护栏**:所有Claude调用计数落库,设置页显示当月调用次数与估算费用;无Key时机械层照常运行,Claude层跳过并在日报标注「AI解读未启用」。立项与重大事件调用开 web_search 工具(`tools=[{"type":"web_search_20250305","name":"web_search"}]`),普通事件解读不开(用事件文本+论点即可)。

## 七、数据与事件流

**data.py 新增接口(全部集中于此,注明用途)**:
- `get_hist2(code, days=520)`:2年日K(250日新高与周MA30需要),不动原 get_hist
- `get_yjyg(period)` / `get_yjkb(period)`:业绩预告/快报(ak.stock_yjyg_em / stock_yjkb_em),按个股匹配最新一期;无数据时基本面闸门以行业指数项兜底
- `get_announcements(code, since)`:公告(ak巨潮/东财公告接口,现场验证可用者)
- `get_stock_news(code)`:个股新闻(ak.stock_news_em)
- `get_industry_index(name)`:行业板块指数日K(东财 stock_board_industry_* 系列,现场验证;申万接口可用则优先)
- 相对强度:用每日筛选已拉取的全池日K本地计算120日涨幅分位,不新增请求

**events 表**:id, code, ts, type(公告/业绩/新闻/技术迁移/行业变档), title, payload, source_url, dedup_hash, claude_read(解读结论)。每日采集只针对池内票+当日候选,按 dedup_hash 去重;个股详情页渲染成时间线。

**新增DB表**(storage.init 增量建表,不动 snapshots):`pool`(code,name,state,各时间戳,platform_price,stop_price,entry_price,position,cooldown_until,sort_score,note)、`thesis`(code,created_at,content_json,version)、`events`、`daily_reports`(d,payload_json)、`ai_usage`(调用计数)。

**设计原则:每屏只回答一个问题。** 首屏问题永远是"我今天要做什么"。
