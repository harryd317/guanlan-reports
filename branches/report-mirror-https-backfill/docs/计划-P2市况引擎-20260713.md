## 两个实现决策(偏离设计文字面,记录理由)

1. **回填起点 2015-01-01 而非"5年"**:设计§5.2 规定因子/阈值只准用 2015~2021 段设计,
   而宽度因子(涨跌家数/新高新低占比)依赖本库——库只有 5 年则宽度因子在设计段不可得,
   违反"因子准入三件套"(全期同口径可得)。约 2550 交易日×2 接口≈5100 次调用,
   5000 积分几十分钟量级,断点续传本来就要做,成本差异可忽略。
2. **独立 market.db**(不进 screener.db):~2550 日×约4500 只≈千万行级,混进业务库会让
   .backup/迁移备份全变胖;跨库无 JOIN 需求(消费方 regime.py 只读聚合)。

## Task A1: market_data.py 子系统(库+回填+增量+对账)

**Files:** Create `market_data.py`;test ㉕ 节 TP4 前缀

- Schema(market.db,WAL):
  - `market_daily(trade_date TEXT, ts_code TEXT, close REAL, pct_chg REAL, high REAL,
    low REAL, amount REAL, PRIMARY KEY(trade_date, ts_code))`
  - `adj_factors(trade_date TEXT, ts_code TEXT, adj_factor REAL, PRIMARY KEY(trade_date, ts_code))`
  - `fill_progress(trade_date TEXT PRIMARY KEY, daily_n INT, adj_n INT, filled_at TEXT)`
    ——断点续传凭据:两接口都落了才算完成;重跑幂等(INSERT OR REPLACE)。
- `backfill(start="2015-01-01", end=today)`:交易日历(data.get_trade_dates_gate 同源或
  pro.trade_cal)逐日 `pro.daily(trade_date=d)` + `pro.adj_factor(trade_date=d)`,
  **按 trade_date 维度拉取**(point-in-time 免费正确,设计§5.1 划重点);
  已在 fill_progress 的日期跳过;限流指数退避(1/2/4/8…最多 5 次,整分钟窗冷却);
  每 50 日打进度;可 Ctrl-C 随时断,重跑续传。
- `update_today()`:EOD 后增量(当日两接口各一次);当日拉不到**绝不拿旧数据充当日**
  (设计红线),只记日志等哨兵下一轮。空数据(节假日)不落 fill_progress。
- `breadth(d)`:当日涨跌家数(pct_chg 正负计数)、20日新高/新低占比(close×adj_factor
  后复权滚动窗,**未复权价除权日出假新低**——设计划重点);全市场不剔 ST。
- 对账验收:`spot_check(dates)` 抽日输出涨跌家数,人工比对第三方,误差>2% 查复权/退市。
