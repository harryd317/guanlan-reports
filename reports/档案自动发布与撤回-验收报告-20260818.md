## 一、新规则状态机

| 当前状态 | 条件 | 系统动作 | 结果 |
|---|---|---|---|
| 待终审 | 尚无 Kimi 审校意见 | 不动作 | 继续等待 Kimi 审校 |
| 待终审 | Kimi 结论为“改后再审”、“重写”、“不通过”或“未通过” | 不动作 | 保持原状态，等待返修 |
| 待终审 | Kimi 结论通过，但镜像哈希或正式档案/v2 校验未齐 | 不发布 | 显示缺失条件，继续等待 |
| 待终审 | Kimi 审校事件已落库且结论通过（含复尺通过）＋40/64 位镜像提交哈希＋正式档案通过 v2 与档案门校验 | 自动执行 finalize | `resolved`，S8 档案门槛解锁 |
| 已发布 | 段睿或 Kimi 经镜像投递撤回指令，并提供原因和 40/64 位镜像提交哈希 | 标记无效并写审计 | `withdrawn`，S8 档案门槛立即重新锁定 |
| 已撤回 | 日常队列推进或季度复核 | 保留撤回状态 | 不会被自动恢复为有效档案 |

通过结论采用严格解析：先判断否定词，再接受“通过”或“复尺通过”。只有审计链中最新 `external_review` 事件的 actor 精确为 `Kimi` 时才能触发；其他 actor 写入“通过”不会发布。

## 二、服务端与页面

- 新增幂等收敛：审校意见回投后立即尝试自动发布；生产启动时再扫描一次已齐备的存量项。
- 旧 `/finalize` 服务端路由保留以维持接口兼容，但域层已强制校验 Kimi 通过意见，不能绕过新规则。页面不再调用该路由。
- 新增撤回入口：`POST /api/s8/archive-queue/{industry_code}/withdraw`；入参仍是现有风格的 `actor`、`reason`、`mirror_commit_hash`，未改操作日志字段。
- 撤回 actor 仅允许 `段睿` 或 `Kimi`；其他名称、空原因、非 40/64 位哈希均返回 409，不改状态。
- 待终审页已移除“发布/退回/改后发布”三按钮及 prompt 流程，改为自动发布状态和“申请撤回”说明。
- 固定警示原文保留：“AI 生成初稿 · 未经审校/终审不作为核心股依据”。
- 撤回页保留历史正文作审计证据，页头和陶土色卡显示“已撤回”、撤回原因以及“不构成有效 S8 档案依据”。
- 未新增数据库表或字段；状态与审计沿用 `archive_queue`。

### 自动发布（生产实录）

```json
{
  "actor": "auto-on-kimi-review",
  "time": "2026-08-18T14:22:36+08:00",
  "action": "publish",
  "reason": "e7384dc3206468908a334d730ee6a7cec6474719"
}
```

饲料与通用设备的审计记录均由 3 条增至 4 条；新增的第 4 条均为自动发布。

### 撤回（生产等效夹具，未对生产档案执行撤回）

```json
{
  "actor": "Kimi",
  "action": "withdraw",
  "reason": "审校来源页已撤回；镜像提交 6666666666666666666666666666666666666666"
}
```

撤回后队列状态为 `withdrawn`，原 `archive_id` 保留作追溯，但 `is_published=false`；S8 仅认 `resolved` 为档案门槛通过，因此立即重锁。
